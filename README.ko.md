# BurnGuard

**이미 결제해서 쓰고 있는 Claude Code나 Codex로 동작하는 오픈소스 Claude Design 대안이에요.**

![한 줄 프롬프트가 BurnGuard 랜딩페이지가 되고, 캔버스에서 제목을 고치는 장면](doc/images/burnguard-demo.gif)

*v0.5.25에서 Claude Code(Sonnet, 추론 강도 LOW)로 디자인 시스템 없이 녹화했어요. 5분 걸린 생성 구간만 빨리 감았고, 나머지는 실제 속도예요.*

[![Latest release](https://img.shields.io/github/v/release/ashmoonori-afk/BurnGuard)](https://github.com/ashmoonori-afk/BurnGuard/releases/latest) [![Downloads](https://img.shields.io/github/downloads/ashmoonori-afk/BurnGuard/total)](https://github.com/ashmoonori-afk/BurnGuard/releases) [![License](https://img.shields.io/github/license/ashmoonori-afk/BurnGuard)](LICENSE) [![GitHub stars](https://img.shields.io/github/stars/ashmoonori-afk/BurnGuard?style=social)](https://github.com/ashmoonori-afk/BurnGuard/stargazers)

⭐ BurnGuard가 시간을 아껴 드렸다면, 스타 하나가 다른 분들이 BurnGuard를 찾는 데 도움이 돼요.

AI로 웹사이트·슬라이드·그래픽을 만들고, 캔버스에서 다듬고, 파일은 그대로 가져가세요. BurnGuard는 Windows와 macOS용 로컬 디자인 작업 공간이에요. 사용 중인 Claude Code 또는 Codex 연결을 가져와 디자인 시스템을 고르고, 실시간 미리보기 옆에서 작업해요. 프로젝트와 재사용 가능한 디자인 시스템은 내 컴퓨터에 저장하고, AI 요청은 선택한 제공업체로 보내요.

## 디자인 방향으로 시작하기

온보딩에서 형식을 고르고 프로젝트를 설명한 뒤 등록된 디자인 시스템을 선택해요. 목록을 검색하거나 새로 고쳐 새로 등록된 시스템을 불러올 수 있고, 디자인 시스템 없이 시작해도 돼요.

번들 카탈로그에는 **테마 41개**가 있고, 그중 **오리지널 테마가 31개**예요. 테마마다 내비게이션·히어로·푸터 조합이 달라서 타이포그래피와 색상뿐 아니라 배치, 비율, 반응형 규칙도 다르게 가져가요. 이 레이아웃은 Supahero, Navbar Gallery, Footer Design의 레퍼런스를 바탕으로 했고, 각 테마에 출처가 기록돼 있어요. 오리지널 샘플 시스템과 프롬프트 프리셋에도 레이아웃 규칙이 들어 있어요. 지원하는 파일, 웹사이트, 저장소, Figma 자료에서 내 시스템을 추가한 뒤 검토하고 게시해 프로젝트에 쓸 수 있어요. [레퍼런스 레이아웃 41개 보기](<design system themes/>)

![디자인 시스템 검색, 새로 고침, 선택 컨트롤이 있는 프로젝트 온보딩](doc/images/readme-design-system-picker.png)

*실제 앱의 디자인 시스템 선택 화면이에요. 미리보기가 없는 시스템도 이름으로 선택할 수 있어요.*

시스템 개요를 열면 내비게이션·히어로·푸터 규칙을 확인할 수 있어요. **방향 설정과 생성은 같은 규칙을 사용해요.** 간결한 프롬프트도 마찬가지예요. 방향 미리보기 3개는 선택한 시스템의 구조 안에서 메시지, 근거, 행동 유도의 강조점만 달리해요. 이 미리보기는 구조 요약이라 실제 렌더링 결과에는 더 풍부한 디테일이 들어갈 수 있어요. 시스템을 고르기 전이나 규칙이 바뀌기 전에 저장한 방향은 현재 시스템 기준으로 다시 만들 수 있어요.

![간결한 내비게이션·히어로·푸터 규칙, 그리드 다이어그램, 레이아웃 치수가 보이는 디자인 시스템 개요](doc/images/readme-layout-overview.png)

*실제 Cobalt Atelier 개요예요. 내비게이션·히어로·푸터 요약은 항상 보이고, 영역을 펼치면 전체 규칙을 읽을 수 있어요. 누락된 번들 규칙은 보충하고, 이미 작성된 규칙은 그대로 보존해요.*

![추론 강도 LOW를 선택한 상태에서 같은 Cobalt Atelier 레이아웃 규칙을 사용하는 방향 설정 화면](doc/images/readme-layout-direction.png)

*생성 전, 실제 프로젝트의 방향 화면에서 같은 레이아웃 규칙을 사용하는 모습이에요. 이 캡처는 설정된 안내를 보여 줄 뿐, 측정된 모델 품질 결과가 아니에요.*

데스크톱 패키지에는 **웹사이트 예제 41개**, **생성한 WebP 일러스트 41개**, **Chrome에서 캡처한 웹사이트 썸네일 41개**가 들어 있어요. 디자인 시스템 라이브러리와 프로젝트 온보딩에서 썸네일을 보여 주고, 각 테마 개요에는 스크롤할 수 있는 전용 웹사이트 미리보기가 있어요. 에디토리얼 사이트, 쇼핑몰, 워크스페이스, 문화 페이지 등을 [웹사이트 미리보기 갤러리](design%20system%20themes/previews/index.html)에서 둘러보세요. [테마 토큰 카탈로그](design%20system%20themes/catalogue.html)

![BurnGuard에서 실제 웹사이트 썸네일을 보여 주는 디자인 시스템 라이브러리](doc/images/readme-design-system-library.png)

*번들 웹사이트 썸네일이 보이는 실제 디자인 시스템 라이브러리예요.*

이 예제들은 번들 테마의 기본 디자인을 보여 줘요. 시스템에 미리보기 파일이 이미 있으면 그것을 우선하고, 없을 때는 수정한 시스템 파일이나 게시 기록을 덮어쓰지 않고 번들 레퍼런스를 보여 줘요. 앱 안에서 예제는 공유 로컬 글꼴 저장소를 사용해요.

**글꼴 패밀리 72종**을 라이선스 고지와 함께 번들해요. 번들 글꼴은 하나의 공유 로컬 저장소를 쓰고, 캔버스에서 불러온 글꼴은 앱 창 안에서 프로젝트끼리 재사용돼요. 새 프로젝트는 이 저장소를 참조하고, 독립 실행형 내보내기에는 필요한 글꼴 파일이 포함돼요. [글꼴 목록](assets/fonts/README.md) · [디자인 시스템 형식](<design system sample/README.md>)

## 하나의 작업 공간, 다양한 결과물

| 만들기 | 작업 | 가져가기 |
|---|---|---|
| 웹사이트 | 연결된 페이지, 공통 스타일, 이미지, 재사용 컴포넌트 | HTML/CSS/JS/에셋 ZIP 또는 내 Vercel 계정에 게시 |
| 슬라이드 덱 | 슬라이드 미리보기, 타이포그래피, 발표 모드, 코멘트 | HTML, PDF, PPTX |
| 그래픽 | 사용자 지정 아트보드 크기, 포스터, 여러 프레임 구성 | PNG, PNG 묶음, PDF |
| 로고 | 여러 라운드의 디자인 탐색, 하나를 마스터로 선택 | SVG 마스터¹, 브랜드 가이드라인 PDF 또는 HTML 아카이브 |
| 상세페이지 | 섹션별 이미지가 있는 긴 페이지 | 섹션 경계에 맞춘 PNG/JPEG 조각 |
| 플랫폼 페이지 | 카페24 스마트디자인 또는 아임웹 코드위젯 결과물 | 수동 설치 가이드가 포함된 패키지 |

¹ SVG 마스터 내보내기는 로고 프로젝트에서만 쓸 수 있어요.

![발표·내보내기 컨트롤이 있는 SONNEL 덱을 보여 주는 BurnGuard 슬라이드 편집기](doc/images/readme-slide-workspace.png)

*같은 작업 공간에서 슬라이드 덱도 다뤄요. 캔버스 위에 발표와 내보내기 컨트롤이 있어요.*

PPTX 내보내기에는 슬라이드마다 고해상도 이미지가 들어가고 텍스트는 발표자 노트에 담겨요. 개별 요소는 BurnGuard의 HTML 작업 공간에서 계속 편집할 수 있지만, 편집 가능한 PowerPoint 객체로는 내보내지지 않아요.

## 보이는 곳에서 바로 다듬기

- **캔버스에서 편집해요.** 요소를 선택해 크기와 회전을 바꾸고, 타이포그래피와 여백을 조절하고, 색상을 다룰 수 있어요. 저장된 리비전과 실행 취소로 이전 결과로 돌아갈 수 있어요.
- **정확한 위치에 코멘트를 남겨요.** 콘텐츠에 피드백을 고정하고 AI 수정 요청을 보내세요. 핀은 스크롤해도 붙어 있고, 저장된 핀을 누르면 코멘트가 다시 열려요. 캔버스 위에 마우스를 올린 채 Windows/Linux에서는 **Ctrl+Space**, macOS에서는 **Control+Option+Space**를 누르면 빠른 코멘트를 남길 수 있어요.
- **자료를 추가해요.** 지원하는 PDF, 슬라이드 덱, 문서, 이미지, 텍스트를 첨부하거나 내보낸 HTML 프로젝트 ZIP을 가져오세요. 첨부 원본은 게시되는 웹사이트 에셋과 따로 보관해요.
- **공유하기 전에 검토해요.** 품질·UX 패널이 문제를 찾아 주고 수정 작업을 제안해요. 결과는 권장사항이니, 내보내거나 게시하기 전에 렌더링 결과를 직접 확인하세요.

### 이미지, 차트, 3D

이미지에 디자인 속 역할을 주세요. 제품 히어로, 캠페인 장면, 설명용 일러스트, 배경 등이 될 수 있어요. BurnGuard에는 13개 분야에 걸친 **이미지 표현 스타일 21개**와 **용도 레시피 38개**가 있어요. 생성 이미지는 **기본적으로 실사**예요. 요청하지 않으면 추상 이미지는 만들지 않고, 이미지 프롬프트는 사진가의 브리프처럼 작성하며, 인공적인 피부, 빛나는 배경, 깨진 글자 같은 생성 이미지 특유의 흔적은 검수 단계에서 걸러내요. 비사진 표현은 직접 고르거나 요청했을 때만 적용돼요. 디자인에 이미지가 필요하면 생성하도록 안내하지만, 요청한 생성은 설정된 제공업체가 지원해야 해요. 그래픽 생성에는 로그인된 Codex 연결이 필요해요. [이미지 생성 가이드](doc/image-production.md)

**차트** 패널에서 area, line, bar, composed, radar, pie, radial, Sankey 차트를 추가하세요. 스프레드시트 행을 붙여넣고 색상을 고치면, 이식 가능한 SVG가 원본 데이터와 함께 HTML에 저장돼요. **3D** 패널은 번들 Three.js 오브젝트와 AI 장면 수정을 지원해요. [차트 가이드](doc/charts.md)

**SONNEL**, **FOLIOVER**, **ODDWARD**, **VELUNE**, **HALIDE**를 둘러보세요. 오리지널 컬렉션마다 웹사이트, 6장짜리 슬라이드 덱, 그래픽, 디자인 시스템이 들어 있어요. [샘플 컬렉션](samples/original/README.md) · [이미지 레시피 갤러리](doc/images/image-recipes/README.md)

## 시작하기

1. **설치해요.** [GitHub Releases](https://github.com/ashmoonori-afk/BurnGuard/releases/latest)에서 Windows 또는 macOS 패키지를 받으세요. Windows에서는 설치 프로그램을 쓰거나 포터블 ZIP을 전부 풀고 `BurnGuard.exe`를 열어요. macOS에서는 설치 프로그램을 쓰거나 포터블 앱을 응용 프로그램 폴더로 옮겨요. 패키지는 현재 서명되어 있지 않아요.
   - **macOS:** 처음 실행하면 Gatekeeper가 막아요. 앱을 한 번 열어 본 뒤 **시스템 설정 > 개인정보 보호 및 보안 > 그래도 열기**를 누르세요. 터미널에서 `xattr -dr com.apple.quarantine "/Applications/BurnGuard.app"`를 실행해도 돼요. 참고: macOS 15 이상에서는 Control-클릭으로 여는 방법이 더 이상 통하지 않으니 시스템 설정 경로를 사용하세요.
   - **Windows:** 서명되지 않은 Setup.exe나 포터블 .exe를 실행하면 SmartScreen이 "Windows의 PC 보호" 창을 띄울 수 있어요. **추가 정보**를 누른 뒤 **실행**을 누르세요.
2. **예제를 둘러봐요.** AI 제공업체를 연결하기 전에 번들 프로젝트를 열고 캔버스를 먼저 써 보세요.
3. **CLI를 연결해요.** Claude Code 또는 Codex CLI를 설치하고 로그인한 뒤, 설정에서 연결과 모델을 고르세요. **추론 강도 보통(medium)과 바닐라 모드가 기본값이에요.** 바닐라 모드는 개인 플러그인과 지시문은 제외하고 BurnGuard의 프로젝트 맥락은 유지해요.
   - **Codex 작업 진행 감지 (선택, 기본값 꺼짐):** 설정에서 **Codex 작업 진행 감지**를 켜면 오래 조용한 Codex 단계가 멈춘 것으로 중단되지 않아요. 켜져 있는 동안 Codex 사용량 지표는 이 컴퓨터의 BurnGuard로 전송되고, 직접 설정한 OpenTelemetry 대상은 Codex 지표를 받지 못해요.
4. **프로젝트를 만들어요.** 형식과 디자인 시스템을 고르고 브리프와 참고 자료를 더한 뒤, 생성하고 다듬어요.
5. **내보내거나 공유해요.** 프로젝트 파일을 내려받거나, 웹사이트는 **공유 → 현재 결과물 준비 → 공개 게시**로 내 Vercel 계정에 게시하세요.

| 요구 사항 | 세부 내용 |
|---|---|
| Windows 데스크톱 | Windows 10/11 x64, .NET Framework 4.8, Microsoft Edge WebView2 Runtime |
| AI 생성 | 설치 및 로그인이 끝난 `claude` 또는 `codex` CLI와 해당 제공업체 계정 |
| 렌더링과 내보내기 | 지원되는 Chrome·Edge 또는 Chromium. 사용 가능 여부는 설정에서 확인해요 |
| 업데이트 | Windows와 macOS 릴리즈 피드. 패키지를 교체할 때 로컬 프로필은 그대로 두세요 |

Vercel 게시에는 내 토큰과 선택 사항인 팀 ID가 필요해요. 붙여넣은 토큰은 그 게시 동안만 메모리에 두고, 설정에 저장한 토큰은 이 컴퓨터의 로컬 설정 파일에만 보관해요. 호스팅 요금제와 방문자 접근 권한은 Vercel 설정을 따라요. 카페24·아임웹 패키지는 직접 설치해야 하며, 실제 고객 쇼핑몰에서는 검증하지 않았어요.

## 내 프로젝트는 내 컴퓨터에 있어요

BurnGuard는 데이터베이스, 프로젝트, 설정, 시스템, 내보내기 캐시를 `~/.burnguard`(Windows에서는 `%USERPROFILE%\.burnguard`)에 보관해요. 앱을 업그레이드할 때 이 프로필을 지우지 마세요.

생성할 때는 선택한 맥락이 설정한 제공업체로 전송돼요. 가져오기와 게시에도 네트워크를 쓸 수 있어요. 로컬 서버는 루프백에만 바인딩하고, 실행 권한을 확인하며, 생성된 페이지는 샌드박스에서 격리해요. [보안 모델](doc/01-architecture.md#7-security-and-safety-model)

## 소스에서 실행

CI에 고정된 **Bun 1.3.14**를 사용하세요.

```sh
git clone https://github.com/ashmoonori-afk/BurnGuard.git
cd BurnGuard
bun install --frozen-lockfile
bun run scripts/dev-launcher.ts
```

런처는 프런트엔드를 `http://127.0.0.1:5173`에서 열고, 백엔드는 `127.0.0.1:14070`을 사용해요. Ctrl+C로 종료해요. Windows의 `Start-BurnGuard.bat`은 개발용 소스 빌드 런처예요(Bun과 .NET 8 SDK 필요). 일반 사용자는 GitHub Releases의 설치 프로그램을 받으세요. 소스를 고친 뒤에는 `--rebuild`를 사용하세요.

저장소의 테마 예제를 보려면 브라우저에서 `design system themes/previews/index.html`을 열세요. 이 페이지는 번들 로컬 글꼴과 이미지를 사용해요. 테마 토큰을 고친 뒤에는 토큰 카탈로그와 웹사이트 미리보기를 다시 빌드하세요.

```sh
bun run catalogue
bun run previews
```

`previews`는 HTML을 다시 만들고 기존 일러스트를 재사용하며, 이미지 제공업체를 호출하지 않아요. 커밋된 웹사이트 썸네일을 갱신하려면 그다음에 Node.js와 Chrome이 설치된 환경에서 `bun run previews:thumbnails`를 실행하세요. 실제 페이지를 Chrome에서 캡처해요.

```sh
bun run typecheck
bun run lint
bun run build:frontend
bun test
```

테스트는 저장소 루트에서 실행하세요. 그래야 preload가 격리된 임시 프로필을 제공해요. 브라우저 QA에는 Node.js와 Chrome/Edge가 필요하고, Windows 러너에서는 Bun 실행 파일의 절대 경로가 필요할 수 있어요. [기여 및 네이티브 빌드](doc/CONTRIBUTING.md)

## 변경 내역

### 0.5.28

- 추출한 디자인 시스템으로 만든 새 웹사이트 프로젝트가 이제 클래스 기반 페이지 골격에서 시작하고, 추출한 히어로 이미지를 유지하며, 버튼·부제목·푸터 텍스트에 읽기 좋은 색을 써요. 이미 편집한 페이지는 시작 템플릿으로 바뀌지 않아요.
- 품질 검토가 각 섹션을 레퍼런스 스크린샷과 비교하고 가장 약한 섹션을 잘라 내서, 한 번에 한 섹션씩 고칠 수 있어요. 블록 윤곽 이미지가 각 레퍼런스 스크린샷 옆에 저장돼요.
- 웹사이트 추출이 더 정확해졌어요. 소제목, 브랜드 이름, 색상 토큰, 히어로 이미지를 더 안정적으로 측정하고, 가져온 SVG 이미지를 정리하고, 스타일시트 리다이렉트는 같은 사이트 안에서만 허용하고, 레이아웃을 측정하지 못했을 때는 그 이유를 기록해요.
- 설치된 AI 도구가 없으면 전송이 비활성화되고 이유와 설정 링크가 표시돼요. 중단되거나 실패한 턴은 항상 중단 또는 실패로 표시되고, 다른 메시지가 실행 중일 때 보낸 메시지는 반쯤 기록된 턴을 남기지 않고 깔끔하게 거절돼요.
- BurnGuard가 백그라운드에서 다시 시작되면 열려 있는 창이 알려 주고 새로 고침을 제안해요. 휴대폰 너비에서도 작업 공간, 캔버스 도구, 내보내기를 쓸 수 있어요.
- 모델이 지원하면 추론 강도 기본값이 medium이 되고, Claude·Gemini·프리셋 모델 목록은 현재 공식 모델 ID를 사용해요.
- 캔버스는 페이지가 쓰는 글꼴만 불러오고, 페이지가 그려질 때까지 렌더링 상태를 보여 줘요. 스타일 사이드 에디터는 입력한 값을 유지해요.
- 매우 크거나 특이한 프로젝트 파일도 내보내기가 훨씬 빠르고 안전하게 처리돼요. 악센트가 있는 macOS 파일 이름을 유지하고, 다운로드 파일 이름을 올바르게 인코딩해요.
- 오류 메시지에 더 이상 개인 파일 경로나 원시 시스템 오류 문구가 나오지 않고, 설정 오류는 복구 방법을 설명해요. 한국어와 중국어 문구도 보완했어요.
- macOS 앱이 Windows 앱과 같은 데스크톱 규칙을 따르고, 업데이트 확인이 프리릴리즈 버전을 올바른 순서로 정렬해요.

### 0.5.27

- 프로젝트를 이식 가능한 `.burnguard-project` 번들로 내보내고 다른 컴퓨터에서 복원할 수 있어요. 저장된 제공업체·접근 토큰과 로컬 설정은 제외되며, 복원하면 항상 새 프로젝트가 만들어져요.
- 핸드오프 내보내기에 기계가 읽는 매니페스트, `HANDOFF.md`, 코딩 CLI용 프롬프트가 추가됐고, Claude Code나 Codex에서 이어 작업하는 복사 가능한 명령도 들어 있어요.
- 설정 > 런타임 진단에서 CLI 연결별 버전과 기능, 최근 생성이 멈춘 단계를 볼 수 있어요. 실패하거나 중단된 프로젝트는 이미 저장된 파일에서 이어서 진행할 수 있어요.
- 시각 품질 가이드가 웹사이트, 덱, 그래픽, 로고, 다이어그램까지 다뤄요. 품질 패널에 구분 대시, 플레이스홀더 문구, 아이브로 라벨, 반복되거나 줄바꿈된 주요 CTA, 악센트·모서리 반경 개수, 반복되는 인접 섹션에 대한 권장 점검이 추가됐고, 웹사이트용 렌더링 여정 점검(어디로도 가지 않는 링크, 가로로 스크롤되는 모바일 내비게이션, 보이지 않는 키보드 포커스, 로딩 중 레이아웃 이동)도 생겼어요.
- GIF 첨부를 받고, 메타데이터에 SVG 텍스트가 들어 있는 이미지도 디코딩돼요. WebP 파일은 디코딩 전에 검증하고, 신뢰할 수 없는 이미지의 색상 샘플링은 별도 프로세스에서 실행해요.
- 디자인 대안을 2~4개 생성해 나란히 비교하고, 하나를 승격하고 나머지는 삭제할 수 있어요.
- PDF, PNG, PNG ZIP, PPTX 내보내기가 캔버스와의 페이지별 유사도 점수를 보여 줘요. 이 점검은 경고만 하고 다운로드를 막지 않아요.
- Figma JSON 내보내기(선택적으로 프레임 이미지 포함)를 디자인 시스템 토큰에 맞춘 불변 레퍼런스로 가져올 수 있어요. Figma 계정 토큰은 필요 없어요.
- 웹사이트 디자인 시스템을 페이지 단위로 추출해요(내비게이션, 푸터, 사이트맵, robots.txt 준수). 측정한 레이아웃, 페이지 색상, 글꼴 역할, 에셋 사용 규칙, 에셋 프롬프트가 포함돼요. Chromium이 있으면 소스 페이지를 최대 4개까지 오프라인으로 렌더링해 데스크톱·모바일 너비에서 측정하고, 그 페이지의 레퍼런스 스크린샷을 시스템과 함께 보관해요.
- 추출한 시스템으로 웹사이트를 생성하면 측정값이 강제 제약으로, 시작 스타일시트와 페이지 골격, 시각 목표로서의 레퍼런스 스크린샷, 명확한 우선순위 하나가 함께 전달돼요. 검토는 측정한 레이아웃과 페이지를 비교하고 한 번 수정해요.
- 생성 안내가 모델 계열별 능력 프로필(claude-frontier, gpt-image, standard)을 따라요. Claude Opus나 Sonnet에서는 로고가 제공되지 않으면 일곱 가지 구성 규칙에 따라 토큰으로 CSS·SVG 로고를 디자인하고, 이미지를 생성하는 대신 Openverse와 Iconify(키 불필요)에서 공개 라이선스 사진·일러스트·아이콘을 찾아 출처와 라이선스를 함께 저장해요. Codex의 GPT 모델은 계속 직접 이미지를 생성해요. 웹 검색은 설정에서 끌 수 있고, 모델 선택기는 medium 이상의 추론 강도를 권장해요.
- 생성·수정 프롬프트에 증거 규칙이 들어가요. 시각적 주장은 렌더링된 증거로만 하고, 실행하지 않은 점검은 미검증으로 보고하며, 측정하지 않은 숫자는 쓰지 않아요.
- 첫 실행에서는 시스템 언어(한국어, 중국어 간체, 그 외는 영어)를 따르고, 설정에서 고른 언어가 항상 우선해요. 첫 내보내기나 게시에 성공하면 GitHub 스타를 한 번 물어보는데, 어디로도 아무것도 전송하지 않아요.

- README가 한 줄 프롬프트가 랜딩페이지가 되는 녹화 데모로 시작해요.
- 신뢰할 수 없는 디자인 시스템 소스의 숨겨진 `<template>`·`<noscript>` 마크업을 컨테이너마다 한 번 검증하고 8단계보다 깊게 중첩되면 거부해서, 조작된 마크업이 백엔드를 멈추게 할 수 없어요.
- macOS 릴리즈 스모크 테스트가 툴바 위치 대신 아이콘으로 캔버스 편집 컨트롤을 찾아요. 0.5.25에서 선택 모드가 빠진 툴바에 맞춘 거예요.

### 0.5.25

- 렌더링된 디자인 점검을 실행할 수 없어도(Chromium이 없거나 큰 사이트가 시간 초과) 생성 턴이 커밋돼요. 턴을 거부하는 대신 채팅에 "검토 미완료" 배지가 표시돼요. 반드시 고쳐야 하는 항목은 그 턴이 바꾼 페이지에서만 턴을 막고, 공유 CSS·스크립트·이미지를 바꾼 턴은 모든 페이지를 점검해요.
- 품질 패널이 덱과 고정 크기 그래픽에 해당하지 않는 점검을 해당 없음으로 보고하고, 단순 그라디언트에서도 대비를 측정하며, 고정폭 글꼴을 별도의 글꼴 역할로 다루고, 연결된 스타일시트에서 하드코딩된 색상을 찾고, 내보내기가 가져올 수 없는 원격 글꼴·이미지·프레임을 표시해요.
- 디자인 브리프에 앱 언어가 담기고, UX 검토 결과, 품질·플랫폼 수정 요청, 방향 미리보기, 앱이 만드는 모든 AI 요청이 한국어·영어·중국어로 표시돼요. 모든 서버 오류 코드에 오류 메시지가 있어요.
- 프롬프트 하네스가 서로 충돌하는 규칙(차트, 팔레트, 브레이크포인트, 사회적 증거, 지도 임베드, Windows 전용 PowerShell)을 정리하고, 한글 타이포그래피 규칙을 추가하고, 프로젝트마다 Lucide 아이콘 레퍼런스를 준비하고, 3D·차트 계약은 요청이 있을 때만 적용하고, 전체 디자인 시스템 토큰 블록을 제공하고, 간결 모드에서는 고정 규칙을 줄여요.
- 캔버스: 편집 패널에서 이미지 소스와 링크 대상을 고칠 수 있고, 해결된 코멘트를 다시 열 수 있고, 새 코멘트는 편집기가 열리고, Ctrl/⌘+Z로 스타일 조정을 되돌리고, 색상 견본이 페이지 자체 토큰에서 나오고, 번들 글꼴이 모두 나열되며, 중복된 선택 모드가 사라졌어요.
- 홈과 설정: 다크 모드가 모든 화면에 적용되고, 언어가 클릭하면 바로 저장되고, 백엔드 감지에 실패하면 다시 시도 버튼이 나오고, 생성 성공 후 작성 초안이 지워지고, 검색이 모든 프로젝트를 포함해요.
- 웹사이트 가져오기가 페이지를 거부하는 대신 스크립트와 폼을 제거하고, 추출한 토큰에 미디어 쿼리 맥락을 기록하고, 표준 토큰 계약을 출력해요. 시작 템플릿은 `--page-background`를 선언해요.

### 0.5.24

- 새 프로젝트와 시드 샘플이 캔버스, 라이브 미리보기, 발표에서 다시 로드돼요. 번들 글꼴 수가 캔버스 글꼴 한도를 넘어서 생긴 문제였어요.
- PDF와 PNG ZIP 내보내기가 작성된 grid/flex 레이아웃과 페이지 배경을 유지하고, 지연 로딩 이미지를 기다리고, 시드 샘플 그래픽을 아트보드 PDF로 내보내요. PDF로 내보내기엔 너무 큰 덱은 렌더링 전에 분명한 이유와 함께 거부돼요.
- 카페24·아임웹 패키지가 일반 링크를 받고, 모든 페이지와 하위 페이지만 쓰는 에셋을 포함하고, 푸터 스크립트가 계속 동작하고, 글꼴 라이선스를 포함하며, 더는 Chromium이 필요하지 않아요.
- 내보내기에는 문서가 쓰는 번들 글꼴만 들어가고, ZIP 파일에 로컬 타임스탬프가 담기며, 삭제한 프로젝트가 캐시된 내보내기를 남기지 않아요.
- 채팅이 턴의 작업이 실제로 프로젝트에 반영됐는지 알려 줘요. 실패한 덱 검토와 수정도 포함돼요. 요청하면 첨부한 소스 페이지가 슬라이드와 일대일로 대응돼요.
- macOS 앱: Homebrew나 `~/.local/bin`에 설치된 CLI와 Python을 찾고, 외부 링크를 브라우저에서 열고, 표준 ⌘C/⌘V/⌘Q 단축키를 지원하고, 기존 다운로드를 교체하고, 종료 전에 로컬 서버가 멈출 때까지 기다려요.
- Windows 앱: 복구 가능한 WebView2 프로세스 오류에서도 열려 있고 설치된 글꼴을 나열해요. Linux 소스 실행도 설치된 글꼴을 나열하고, macOS와 Linux에서는 프로필마다 백엔드 하나만 소유해요.
- 설정이 공유 프로필과 기기별 자격 증명·정책으로 나뉘었어요.

### 0.5.23

- 로고 프로젝트가 Codex 이미지 출력을 도착하는 대로 보여 주고, 후보 바이트를 그대로 유지하고, 아트보드별로 텍스트를 감사하고, 더 분명한 실패 단계를 보고해요.
- Windows가 job 객체로 백엔드의 프로세스 트리를 소유하고, 배치 제공업체 인자를 안전하게 인용하고, 네이티브 다운로드를 파일 이름으로 라우팅해요.
- 릴리즈 패키징이 초안을 준비하기 전에 Windows와 macOS에서 네이티브 캔버스, 저장, 내보내기를 검증해요.

### 0.5.22

- 탐색 라운드, 선택한 SVG 마스터, 브랜드 가이드라인 결과물이 있는 로고 디자인 프로젝트를 추가했어요.
- macOS: 샌드박스 캔버스가 동작하고, 네이티브 내보내기 다운로드, 설치된 글꼴 목록, PDF 의존성을 위한 앱 전용 Python 환경이 추가됐어요.
- 보안 수정: 압축 해제 전 PNG 디코딩 크기 검사, 디자인 시스템 승격 전 SVG 재검증, 더 엄격한 POSIX 패키지 권한.
- 0.5.20과 0.5.21은 공개 릴리즈되지 않았어요.

### 0.5.19

- 시작 시 검증된 레거시 첨부 전용 아티팩트 리비전을 복구해요. 프로젝트 파일이나 업로드한 원본은 교체하지 않아요.
- 디자인 시스템 표면 규칙을 읽을 때 Windows 줄바꿈을 정규화해요.
- Windows 브라우저 테스트 시작을 고치고 제공업체·렌더 픽스처를 격리했어요. Windows 릴리즈 패키징에 레거시 복구 점검을 포함해요.

### 0.5.18

- 콘텐츠와 이미지가 로드될 때 큰 슬라이드 콘텐츠를 아트보드에 맞춰요.
- 생성을 완료로 표시하기 전에 실제 슬라이드 내용, 슬라이드 수, 런타임, 로컬 이미지를 검증해요. 플레이스홀더를 받아들이지 않고 미완성 결과물은 이어서 생성해요.
- 생성 이미지의 기본값을 실사 피사체로 하고 추상적인 장식 이미지를 피해요.
- 기록용 사양서 04–23과 참고 노트는 로컬에만 두고, 공개 문서 색인을 단순화했어요.

### 0.5.17

- 선택한 프로젝트 형식에 맞는 슬라이드 또는 웹사이트 썸네일을 보여 줘요.
- 생성을 중단해도 생성된 HTML과 에셋을 보존하고, 쓰는 도중 진입점이 사라졌다면 이전 진입점을 복원해요.
- 프로젝트 디자인 규칙을 고정하고, 렌더링된 결과물을 감사하고, 핸드오프 내보내기에 검토 증거를 포함해요.
