# BurnGuard v0.5.35

BurnGuard v0.5.35 adds an **App screens** project format that turns one line
into a set of linked phone or desktop screens you can play through, adds
construction sheet and draw-in exports for logo projects, and ships an
experimental geometry-first logo method that stays off unless you turn it on.

## App screens

- Choose **App screens** on Home and describe an app in one line. BurnGuard
  generates several linked screens, one HTML file per screen under
  `screens/`, plus a `screens.json` manifest that records the sections and
  the screen order.
- **Frame** sets the screen size: **Phone 390 x 844** (the default) or
  **Desktop 1440 x 900**. Only the generated screens use this size; the
  BurnGuard window itself stays a desktop app.
- The **Board** shows the screens side by side, grouped in sections. Each
  screen shows its title, the screens it links to, and **Play from here**;
  each section has **Play section**. Selecting a screen opens it in the usual
  canvas editor, so chat requests change that screen.
- Play opens an overlay that shows the section name and position (for
  example `Main tabs 1 / 2`). **Previous**, **Next** and taps on links inside
  a screen move between screens, and Esc closes the overlay and returns focus
  to the button that opened it.
- A missing or invalid `screens.json` does not break the project: every
  screen is shown in one **Screens** section instead.
- App screens projects can be exported as an HTML ZIP or a developer
  handoff ZIP.

## Construction exports for logo projects

- The logo export menu adds **Construction sheet SVG**, **Construction
  draw-in GIF** and **Construction draw-in MP4**. They are made from the
  project's geometry record (`logo-geometry.json`); until a project has one,
  the three entries stay disabled and show why.
- The sheet SVG is a still drawing of the guides, circles and finished mark,
  checked against the same SVG allowlist as `logo.svg`.
- The GIF plays the construction draw-in at 480 px and 100 ms per frame,
  holds the final frame for 2 seconds and loops. It is limited to 120 frames
  and 8 MiB; past that the export stops with a message that points to the
  sheet SVG.
- The MP4 uses the same frames, encoded as H.264 (constrained baseline) by
  the bundled browser. BurnGuard checks first whether that encoder is
  available; when it is not, nothing is written and the message points to
  the GIF. The encoder check passed in CI on macOS arm64 and Windows x64.

## Experimental: geometry-first logo marks (off by default)

- A second logo method builds a mark from circles, lines, rectangles and
  polygons on a 64-unit grid, combined with boolean operations, and compiles
  it into an exact `logo.svg` made of straight lines and circular arcs.
- Before anyone looks at a mark, measured checks flag edges shorter than
  0.75 units, boundaries that nearly touch (within 0.5 units), guides placed
  less than 0.5 units apart, and counters that fill in at 16 or 32 px.
- The flow asks two questions (which parts, which direction), then goes
  through symbol, wordmark and lockup. Each step needs your approval, and
  the approval is tied to the exact record on disk, so changing an approved
  record reopens that step. The wordmark is set from a bundled open-licence
  font with an exact cap height, and the lockup is composed from the symbol
  and wordmark without a model.
- This method runs only when BurnGuard is started with
  `BG_LOGO_GEOMETRIC=1`, and it applies to every logo type except pictorial
  and mascot. It stays off by default until it has been measured against the
  current logo flow on twelve briefs; with the switch off, logo turns run
  exactly as in v0.5.34.

## Reliability

- When the design review cannot score a page viewport visually, the review
  now records which step failed (`style`, `capture` or `decode`) instead of
  a bare "unavailable".
- macOS CI tests that click inside the sandboxed canvas with system Chrome
  now wait until the frame itself receives pointer input before the first
  click. This removes an intermittent failure where early clicks landed on
  the surrounding page (225 of 225 passes on the macOS runner after the
  change, against 4 failures in 25 before).

## Upgrading

- Four database migrations run on first start (`0028` adds the
  `app_screens` project type; `0029` to `0031` add the three construction
  export formats). As with every migration, BurnGuard first saves a backup
  copy of the existing database under `backups/`.

## Installation

Use the Windows x64 installer or portable ZIP, or the macOS arm64 installer
or portable ZIP. Extract portable packages completely before opening them.
Packages remain unsigned: Windows may require **More info → Run anyway**;
macOS may require **System Settings → Privacy & Security → Open Anyway**.
Verify downloads against the platform-specific SHA-256 files.
