# Image production recipes

BurnGuard combines an image's **job**, its **visual treatment**, and the project's approved content. These are original product instructions, not a collection of copied example prompts. The catalog covers broad creative applications; it does not import individual third-party cases, image files, named campaigns or model availability claims.

## Choose a job and a treatment

In **Direction → Images and copy**, select an image style, copy tone and image purpose. Save the settings. They apply to later requests and persist when reopening the project. Existing images are not regenerated by changing these preferences.

**Automatic** supplies all 38 compact recipes so the model can choose the appropriate role for each asset. Selecting a purpose supplies only that recipe. Both modes include the common production rules and respect explicit user exceptions. This is prompt guidance, not an automatic proof that an image meets every requirement.

## Write the actual prompt

Start with the intended placement and the message the image must communicate. Describe the subject's visible action, identifying details, camera, scale, light, material, palette, crop and area reserved for copy. Use only decisions that affect the result. Preserve facts and approved assets; invent a new composition for each content-image placement.

Example briefs, written for imaginary projects:

- **Product detail / macro:** A brushed-aluminum reading lamp's rotating hinge, shown from a low three-quarter angle so the joint and adjustment tab are visible. Cool window light creates narrow reflections along the curved housing. Keep the supplied geometry unchanged. Leave the right side quiet for a separate HTML caption; no generated lettering.
- **Campaign / watercolor:** A fictional neighborhood seed exchange: two differently gloved hands pass an open seed envelope above a dark-green workbench. Use transparent pigment with a few dry edges around the paper. Keep the exchange central and leave the upper corner open for the approved event title. Make a square composition for this placement only.
- **Brand touchpoint / clay:** An original coiled-loop mascot used as a desk ornament beside an unprinted mailer and a small fabric tag. Show the softened molded seam and a slightly uneven matte finish under a broad side light. Apply the supplied logo later as an editable overlay. Keep the palette from the project's design system.

## Existing production boundaries still apply

- New raster imagery uses the available authenticated Codex image tool. The catalog does not install another provider or assert that a particular image model is supported.
- Real interfaces, long copy, tables and data charts remain editable HTML/CSS/SVG. Image recipes can support those artifacts without replacing their functional content with a screenshot.
- Real location embeds follow the existing map-provider configuration and sandbox restrictions. Generated maps do not count as verified locations.
- New imagery must be distinct across content placements. Renaming, recoloring or cropping a repeated image is not a new composition. Identity marks and functional icons follow the existing exceptions.
- Inspect actual output at its intended size: crop, perspective, anatomy, materials, exact lettering, repeated assets, loading and artboard dimensions. Report unavailable checks honestly. Quality advice does not prevent user-directed export.

## Implementation and checks

The shared `image-prompt-recipes.ts` catalog supplies the UI labels and prompt recipes. `generation-style.ts` preserves the existing version-1 contract and accepts an optional validated `image_recipe`; older saved preferences remain valid. `prompt-image-production.ts` injects the common rules once in both compact and full generation modes.

The automatic block is bounded to 16,000 characters and a selected-recipe block to 4,000 characters. No extra model call, retrieval service, library installation or network access is required to choose a recipe. The catalog is bundled, so future external examples do not silently change runtime behavior.

```powershell
bun test packages/backend/tests/image-prompt-recipes.test.ts packages/backend/tests/design-direction-contract.test.ts packages/backend/tests/design-direction-routes.test.ts packages/backend/tests/design-direction-workflow.test.ts packages/backend/tests/prompt-builder.test.ts

```

These checks cover selection, invalid input, persistence, prompt assembly and browser controls. They do not submit image-generation requests or establish generated-image quality.
