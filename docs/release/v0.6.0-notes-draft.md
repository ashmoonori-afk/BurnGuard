## Release body

**BurnGuard 0.6.0: the open-source Claude Design alternative that runs on the Claude Code or Codex you already pay for.**

### What's new

- **Take a project anywhere.** Export a project as a portable `.burnguard-project` bundle and restore it on another computer. The bundle carries project files, sources, checkpoints and the design system. BurnGuard's saved provider and access tokens and its local configuration are left out; review your own project files and attachments for secrets before sharing a bundle. Restores always create a new project and report missing themes or fonts.
- **Hand off to production.** The handoff export now includes a machine-readable manifest (regions, design tokens, components, routes, mocked interactions and the backend work they imply), a readable `HANDOFF.md` and a prompt for coding CLIs, plus copyable commands to continue in Claude Code or Codex. Nothing is launched from the app.
- **See why a run failed.** Settings > Runtime diagnostics lists each CLI connection with its version and capabilities, plus the stage where recent generations stopped. A failed or interrupted project can resume from the files already saved, without rerunning the turn.
- **Sharper designs by default.** Generation guidance for visual quality now covers websites, decks, graphics, logos and diagrams. The Quality panel adds advisory checks for visible separator dashes, placeholder copy, too many eyebrow labels, repeated primary calls to action, wrapped primary button labels, multiple primary accents, oversized corner radii and repeated adjacent section layouts.
- **More attachments work.** GIF images are accepted, and PNG, JPEG, WebP and GIF files whose metadata embeds SVG text (such as C2PA content credentials) now decode.
- **Safer image handling.** WebP files are validated against the container rules before decoding, and colour sampling of untrusted images runs in a separate process, so a malformed image can no longer take the backend down.
- **Compare visual alternatives.** Generate two to four named alternatives of a design, compare them side by side at fixed desktop and mobile sizes, promote the one you like and delete the rest. Earlier generations stay listed.
- **Check exports against the canvas.** After a PDF, PNG, PNG ZIP or PPTX export, the export status shows a per-page similarity score and side-by-side thumbnails, and checks page counts and proportions. It warns and never blocks the download.
- **Import from Figma files.** Upload a Figma JSON export (with optional PNG or SVG frame images), pick frames and components, and import them as an immutable reference that keeps their text, geometry, auto-layout and typography. Colours, type, spacing and corner radii are matched to your design-system tokens where a token fits. No Figma account token is needed.
- **Design systems from real websites, page by page.** Website extraction discovers the site's pages (navigation, footer, sitemap, robots.txt respected), extracts each page and keeps page-type templates. It measures layout from the source (container, breakpoints, columns, gutter, section rhythm), takes page colours from the page's own background and text, assigns font roles, and writes asset usage rules and asset generation prompts.
- **Closer website reproductions.** When Chromium is available, extraction renders up to four source pages offline (the entry page and one page of each other type), without running their scripts, and stores measured layout per page for desktop and mobile: section order, container, grid, spacing, positions of the hero heading, subheading, call to action and media, and the type scale in pixels. Website generation receives these as hard constraints with tolerances and checks itself against them. Up to two hero images from the entry page's opening region are copied as assets; script-drawn canvases are noted as not capturable.
- **Starts in your language.** On first run the app follows your system language: Korean, Simplified Chinese, or English for every other language. A language you pick in Settings always wins and is kept.
- **A one-time star request.** After your first successful export or publish, BurnGuard asks once whether you would star the project on GitHub. It never repeats, and nothing is sent anywhere.

### Install and update

Windows and macOS installers, portable apps and update feeds are attached. macOS packages target Apple silicon on macOS 14 or later. Keep your `.burnguard` folder; it holds your projects and settings.

Packages are currently unsigned. Cafe24 and Imweb packages require manual installation and have not been validated in a live customer shop.
