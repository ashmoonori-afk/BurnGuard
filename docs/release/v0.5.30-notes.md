# BurnGuard v0.5.30

This update makes failed and narrow revisions safer to work with: review
failures no longer lose the generated result, text-only and image-only
edits are checked before they are published, photographs follow a
reference-first record, and long print exports are checked before they run.

## Recovering and checking your work

- A generation refused because its design review failed can be opened as a
  separate unverified draft. The original project, its revision and its
  audit stay unchanged. The draft stays marked as unverified until an
  audit of its current content passes every check the failed review left
  incomplete; editing it by hand, or an audit that could not measure those
  checks, does not clear the mark.
- A single missing image no longer blanks a project's preview; it shows as
  a broken image while the rest of the page renders.
- Recovery is refused with a plain explanation when the retained output
  has expired, is damaged, or contains files that the failed generation was
  not allowed to publish.

## Narrow edits that stay narrow

- A request can be limited to text only or images only, optionally for
  chosen pages, artboards or elements. Before publishing, BurnGuard compares
  the result with the previous revision: page text, image references,
  image and asset bytes, styles, scripts and page structure. Whitespace
  that changes what is shown, such as text in preformatted blocks or the
  space between two words, counts as a text change. A change outside
  the chosen scope is not published; the finding names the page, element
  and kind of change, and the scope can be widened explicitly.
- An image file shared with an element outside the scope, including a CSS
  background, counts as outside the scope when its bytes change.
- After each edit, the history shows which pages changed, the kind of
  change and the text before and after. This is a source comparison, not
  a rendered pixel comparison, and it is listed without thumbnails.

## Print and export

- The export menu has a print check: page count and size in millimetres and
  pixels, fonts the page actually uses that are missing or loaded remotely
  (fonts BurnGuard bundles count as available), browser readiness, and
  the effective resolution of each placed image after cropping. Images below
  300 ppi get a warning and images below 150 ppi a strong warning, named by
  page and element. The project package export is offered for moving a
  project to another computer.
- The resolution check measures the original pixels of `<img>` elements.
  It does not detect upscaled files and does not measure CSS background
  images.
- Each export step (page load, fonts, layout, rendering and writing) has
  its own time limit. A step that hangs or fails is named in the export
  status with a recovery action, instead of a generic failure.

## Design review and photographs

- A skip link that appears when it receives keyboard focus is no longer
  reported as text overflow. Skip links that never appear, ordinary
  off-page text and clipped text are still reported.
- Findings on elements without a BurnGuard element ID show a CSS selector
  and the measured position, so they can be located.
- Photographs of real-world subjects can carry a placement record: sourced
  references with licences, verified or estimated physical scale, whether
  the references reached the image generator, compared candidates and
  crop-only placement. The record is kept with the project when a result is
  published, restored on rollback, and carried into a recovered draft; it is
  never part of the published files. A placement is shown as reference-verified only when
  all of these are present; otherwise the missing steps are listed. Whether
  the references reached the generator is reported by the generating agent
  and is not checked independently.
- A stretched photograph (64 pixels or larger) and a reference photograph
  copied into the published files are must-fix findings. Cached quality
  results are recalculated under the new rules.

## Reliability

- Browser-based checks on Windows no longer fail partway through when a
  cold browser start is slow. CI now rejects the pattern that caused it.

## Installation

Use the Windows x64 installer or portable ZIP, or the macOS arm64 installer
or portable ZIP. Extract portable packages completely before opening them.
Packages remain unsigned: Windows may require **More info → Run anyway**;
macOS may require **System Settings → Privacy & Security → Open Anyway**.
Verify downloads against the platform-specific SHA-256 files.
