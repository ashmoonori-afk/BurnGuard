# Deterministic PNG logo tracing: design and measured results

Recorded on 2026-10-23 KST. The design and measurements below preserve their historical scope; current source, tests and release gates determine shipped behavior.

## Design

### Deterministic logo tracing before AI finalization

Design and test protocol frozen before implementation, 2026-10-23.

### Source study

Read vtracer `e71343fbcbf469b8a72a255030408a39939162eb` and
visioncortex `0062088c89645aac76c00e066deb7e8f53980dd7`.
The checked-out repositories now declare MIT OR Apache-2.0, rather than
the older single-license descriptions in the task. Retain both requested
notices conservatively; upstream visioncortex has no NOTICE file.

- vtracer `frontend/color_cluster.rs` keys transparency, reduces color
  precision and drives visioncortex's incremental cluster builder.
- visioncortex `color_clusters/builder.rs` first joins similar adjacent
  pixels, then visits clusters by area, merges into the closest-color
  neighbor, and optionally preserves a contrasting patch as a deeper layer.
  `runner.rs::patch_good` absorbs speckles and rejects thread-like regions.
- `path/walker.rs` follows lattice edges separating inside/outside pixels
  and skips straight runs. Diagonally connected components are separated.
- `path/paths.rs`, `simplify.rs`, `reduce.rs` remove staircase corners and
  reduce polygons. `spline.rs` smooths/subdivides polygons, detects corners
  and splice points, then fits cubic Beziers using flo_curves.
- vtracer `compose.rs` stacks solid parent masks underneath child layers.
  Cutout now uses a shared-boundary mosaic graph to avoid hairline seams.

### Smaller scope

Use pure TypeScript, not WASM or a Rust executable. BurnGuard already ships
`@napi-rs/canvas` on Windows x64 and macOS arm64 through
`export-native-modules.ts`; reuse it solely for PNG decode and test rasterization.
No new runtime dependency, native build, download or subprocess is needed.

Decode the pinned PNG buffer after retaining only pixel/transparency/color
management chunks. Native canvas mistakes `<svg` inside C2PA `caBX` metadata
for an SVG; removing text and EXIF alone is insufficient on the supplied PNGs.
File-path decode succeeds on the same bytes. Test both text and C2PA metadata.

Adapt the lattice-edge walking and bounded-error polygon reduction approach.
Replace the hierarchical cluster graph with a deterministic RGB histogram,
weighted palette fitting (at most eight colors), and four-connected masks.
Merge tiny components into an adjacent palette region rather than deleting
foreground pixels. Emit one compound path per color with evenodd holes.
Default to polygon mode to retain sharp logo corners; offer a local quadratic
spline mode for optional smoothing, not the upstream least-squares fitter.
Transparent pixels stay transparent; partially transparent pixels are
thresholded, an explicit limitation for translucent artwork.

Round-1 decision, superseded by the round-2 results below:
retain disjoint palette masks with evenodd holes and an area-only speckle
threshold (four pixels by default, not the upstream four-pixel side length).
On the same frozen set, the attempted cumulative-mask variant grew from
2,093,464 to 2,737,760 bytes. Adding upstream `runner.rs::patch_good`'s
area/perimeter rejection grew it again to 2,767,964 bytes and increased color
error. Discard both experiments, not their unfavorable measurements.
The retained version is still 18.8 times larger than the reference and misses
the size target. It is a draft experiment, not a demonstrated compact replacement.
Bound Douglas-Peucker distance evaluations per contour as well as edge count,
pixels and SVG bytes.
Drop photo mode, gradients, watershed, adaptive thresholding, arbitrary
palettes, hierarchical cluster graphs, mosaic topology, least-squares cubics,
animation and interactive cached segmentation. Binary mode uses a fixed
luminance threshold. Do not imply this is a byte-for-byte port of vtracer.
Bound input pixels, contour complexity and SVG bytes. Cancellation must be
observed between asynchronous batches, not just before a synchronous loop.

uses the existing AI vectorization path. Unexpected errors still fail.

Trace only selected exploration candidates, never moodboard references.
Check the selected digest and normal managed-path/file identity rules.
Validate generated SVG using the existing validator and set
`data-bg-source-exploration` to the exact selected candidate path.
Keep all existing history, provenance, originality, repair, transactional

### Fixed evaluation, defined before code

and `v2-candidate-*.png` files present in the supplied dori directory, plus
`candidate-4.png` as the eighth: the requested name patterns contain seven,
not eight files. Also use all four `option-*-illustration.png` files.
Add six fixed 128 px synthetic marks: rectangle, ring with a hole, diagonal
touch, thin cross, three-color nested mark, and transparent disk. Their
geometry and colors are constants, not generated by a model.

moving between OS/CPU architectures. Re-rendering circles on Linux changes
two PNG identities; reuse the six originally frozen PNGs instead of updating
the lock or accepting different pixels.

Measure each original PNG at its native dimensions with no crop, alignment
search or background removal. Rasterize SVG with the same installed canvas
renderer for both implementations. Compare RGB composited onto white with
mean absolute error (0..255). Also report foreground IoU: pixels differing
from white by more than 24 in any channel. This silhouette metric alone is
insufficient on dark backgrounds, so retain color error and visual checks.
Report original SVG UTF-8 bytes, path count, wall time and validator result.
vtracer 1.0.0-alpha.4 gets the same original input, --max-colors 8,
polygon mode and default speckle threshold; also report its spline output.
This is a matched palette cap, not equivalent clustering or fitting.
Only inject the required source attribute for reference validation; do not
silently sanitize invalid output or omit its cost. Report cold CLI elapsed
time separately from our in-process decode+trace time, not as a speedup.
Run three measured repeats after one warm-up; report medians.

Search both supplied directories for existing AI-redrawn SVGs; compare only
when an SVG can be paired with its actual source. Missing pairs are N/A.

Preserve the original 18-file SHA lock unchanged. Also measure the other five
PNGs in the requested dori glob under a separate supplemental lock: three
earlier candidates and two UI screenshots. Do not count screenshots as logo
acceptance fixtures, and do not pool supplemental rows into the frozen score.

Predeclared acceptance target: validation on 18/18; per-fixture IoU within
0.02 of the matched polygon reference and MAE at most reference + 3/255;
smaller total bytes than the eight-color polygon reference. Show every miss.
Do not tune the fixture set or hide failures to satisfy the target.

Unit tests cover exact binary/threshold behavior, holes, diagonals, sharp
corners, palette cap, speckles, transparency, invalid input, cancellation,
and output budget. Integration drives the real finalize stage and completion
gate without asking the adapter to write SVG or selection. Mutate the
binary threshold comparison and require the focused test to fail, then
restore it and run the relevant suite once. Package notices must be shipped.

### Round 2: compact output under explicit fidelity bounds

Owner request, 2026-10-23 11:23 KST: on the unchanged 18 SHA-locked PNGs,
total SVG bytes must be <= 111,615, mean foreground IoU >= 0.985,
mean RGB error <= 1.5/255, and validation 18/18. Keep the same renderer,
white compositing, foreground threshold and timing harness. The five
supplemental PNGs remain separate. No fixture-name-specific tuning.

First remove representation overhead: choose shorter absolute or relative
polygon segments and omit separators before negative coordinates. Polygon
coordinates already lie on integer pixel vertices; do not claim a new
rounding gain there. One compound path per palette color already exists.

Then scale the default Douglas-Peucker tolerance with image dimensions,
while preserving explicit zero-tolerance tracing for exact contour geometry.
Do not restore every original point when a nonzero-tolerance contour reduces
to a line: discard that subpixel contour instead. For fully opaque input,
paint the largest palette region as a solid background before other masks;
small discarded holes then reveal a stable paint rather than transparency.
Never paint that background for transparent input. Check synthetic thin
marks, holes and diagonal contacts independently.

If these simpler changes still miss the target, absorb small connected
antialias regions into adjacent stable regions before tracing. Only consider
upstream spline fitting if polygon reduction and compact encoding are not
enough. Report the measured compromise and every missed target; do not claim
lower RAM or a pure-engine speedup.

The first round-2 measurement reached 111,514 bytes but mean IoU was only
0.983392 (MAE 1.361233/255, validation 18/18), so it failed. Nearby fitted
palette colors still create separate antialias boundaries. Coalesce fitted
colors within squared RGB distance 3 * 16^2, keeping the earlier
centroid, and reduce simplification from max-dimension/512 to /640. The
color cap stays at eight; no fixture-specific palette or tolerance is used.

The accepted round-2 measurement is 41,656 total bytes, mean IoU 0.988051,
mean MAE 1.035609/255 and SVG validation 18/18. All four owner-set targets
pass. Full logo regressions pass 429 tests; typecheck and OS coverage pass.
Stop optimizing at this measured result. Palette coalescing remains lossy
even at zero geometry tolerance; tiny contours may disappear at nonzero
tolerance. Keep the reference, mean/individual distinction and unfavorable
before/after accuracy changes in the measured results below.

#### What changed in round 2

- Choose shorter absolute/relative polygon commands, omit repeated command letters and separators before negative coordinates. Polygon vertices were already integers; no new coordinate-rounding benefit is claimed.
- Scale default Douglas-Peucker tolerance to max(0.75, maximum image dimension / 640). Keep explicit zero tolerance for exact contour geometry. Nonzero-tolerance contours that collapse below three points are discarded instead of restoring every old point.
- Paint the largest palette region as a solid background only when every label is opaque. Other colors remain compound masks with holes. Transparent and binary-background pixels do not receive a background fill.
- Coalesce nearly identical fitted colors within squared RGB distance 3 * 16^2. This removes redundant antialias boundaries while retaining the existing eight-color cap and one compound path per remaining color. This quantization is lossy, including with zero geometry tolerance.
- Keep the existing candidate identity, source attribute, allowlist, byte/work budgets, cancellation, publication and AI fallback/tidy-up contracts. No upstream spline fitting, native binary, WASM or dependency was added.

The first round-2 candidate used dimension/512 tolerance without palette coalescing: 111,514 bytes, mean IoU 0.983392, MAE 1.361233 and validation 18/18. It failed IoU and was not selected. The accepted candidate has four passing targets; optimization stopped there.

##### Acceptance and unsuccessful variants

- Validation: 18/18 passed, all under the existing 1 MiB per-file limit, with the selected-source attribute.
- Relative fidelity: 18/18 met IoU >= polygon reference - 0.02 and MAE <= reference + 3. No fidelity-threshold misses were hidden.
- Compactness: FAILED. Ours totals 2,093,464 bytes versus 111,615 reference bytes. Fewer compound path elements do not mean fewer contours or smaller files.
- A cumulative-mask experiment produced 2,737,760 bytes, mean IoU 0.990383 and MAE 0.781886. Adding upstream's area/perimeter thread rejection produced 2,767,964 bytes, IoU 0.990174 and MAE 0.822320. Both were worse than the retained disjoint masks and were removed. The same 18 inputs and identities were used each time.
- The final source was remeasured after selection. All IoU, MAE, byte counts, path counts and validation outcomes exactly match the first disjoint-mask run. The final modules also bound polygon-reduction distance evaluations.

##### What was ported and what was dropped

Adapted vtracer/visioncortex's staged segmentation-to-vector pipeline, transparency separation, four-connected lattice-edge boundary walking with straight-run skipping, holes, and bounded-error polygon reduction. The polygon reduction follows the approach credited upstream to simplify-js, with an iterative work list and explicit work budget. MIT, Apache-2.0 and conservative BSD notices are retained in source, NOTICE and THIRD_PARTY_NOTICES.md; packaging includes the notice file.

Replaced hierarchical clustering with a deterministic RGB histogram and weighted palette fitting capped at eight colors. Dropped upstream cluster hierarchy, mosaic graph, least-squares cubic fitting, full parent-layer composition, watershed/photo modes, gradients and adaptive thresholding. The attempted thread rejection and cumulative masks were discarded after measurement. Optional local quadratic rounding is not the upstream spline fitter. This is a partial algorithm adaptation, not a byte-for-byte port of the entire engine.

Pure TypeScript reuses BurnGuard's existing native canvas decode path on the supported platforms. WASM or a Rust CLI would add packaging/build/runtime machinery; neither is shipped. This avoids dependency growth, but has not demonstrated smaller SVGs or lower memory usage.

##### Integration and regression evidence

On explicit candidate selection, turns.ts pins the expectation, verifies the candidate file and digest, and stages logo.svg and the manifest selection before invoking the AI adapter. The SVG passes the existing allowlist. A ready context tells the adapter to reuse it for guidelines; expected input, empty-output or budget failures retain the existing AI vectorization route. Explicit AI tidy-up remains possible. Unexpected errors still fail, and publication, provenance, originality, cancellation, repair and rollback checks remain in charge.

The supplied candidate PNGs contain a caBX C2PA chunk with an embedded SVG string. Native canvas loaded the file path successfully but misclassified the byte buffer as SVG. Removing only text/EXIF did not fix it. Decode now retains pixel, transparency and color-management chunks while dropping non-rendering metadata; the pinned original file and digest stay unchanged. Unit regressions cover tEXt and caBX.
