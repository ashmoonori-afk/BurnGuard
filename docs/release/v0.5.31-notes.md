# BurnGuard v0.5.31

BurnGuard v0.5.31 lets you create a project and start the first generation in
one action, save chat corrections as design-system rules or project
instructions, import and export design systems as a single `DESIGN.md` file,
preview websites at desktop, tablet, and phone widths, compare before and
after thumbnails in revision history, and open live projects in your file
manager or coding agent.

## Project creation and onboarding

- Creating a project starts with your idea. BurnGuard suggests an editable
  project name from that idea, makes the audience field optional, shows up to
  four design-system suggestions inline, and puts detailed brief options under
  **Advanced**. Selecting **Create and generate** creates the project and
  sends the initial request immediately. If the request fails to send, the
  project remains open and your text stays in the message composer so you can
  send it again.
- On a fresh install, Home displays a dismissible first-run card. It checks
  whether Claude Code and Codex are ready to use, need sign-in, or are not
  installed, links directly to Settings through **Set up**, and lets you
  create and generate your first website project from the same card.
- All 15 bundled example cards on the Examples view (five sample brands across
  website, slide deck, and graphic formats) now include **See the brief** and
  **Start from this**. **See the brief** shows the audience and objective in
  Korean, English, or Simplified Chinese. **Start from this** opens the new
  project dialog prefilled in your current interface language without copying
  the finished sample.

## Design systems, rules, and project instructions

- Each design system can store up to 60 **Do** and **Don't** rules (up to 280
  characters per rule). You can add or delete rules on the system overview
  page, and every generation that uses the system receives them automatically.
  If a saved rule list is damaged, generation and the system view keep the
  valid rules and skip damaged entries, while rule edits refuse to overwrite
  the damaged list until it is fixed.
- Any registered design system, including built-in themes, can be downloaded
  as a single `DESIGN.md` file or imported from a `.md` file (up to 256 KB and
  200 tokens). YAML front matter stores color, typography, spacing, radius,
  shadow, and general tokens (including single-quoted and double-quoted values
  such as font stacks). Markdown headings store layout notes, and **Do** and
  **Don't** lists become system rules.
- Every project has a **Project instructions** button in the top bar (and in
  the **More** menu on narrow screens). It stores up to 4,000 characters of
  instructions (such as tone, audience facts, fixed numbers, or forbidden
  words) that travel with `.burnguard-project` backups and are included with
  every request in the project.
- Every follow-up user message in chat after the initial brief has a **Keep as
  rule** button beside **Revert this turn**. It drafts a short rule from your
  correction, selects **Do** or **Don't** based on negative phrasing in
  Korean, English, or Chinese, and saves your edited text to **Project
  instructions** or to the project's design system. If the rule list is the
  only pending change to the project's pinned design system, BurnGuard updates
  the project baseline immediately for the next turn.

## Canvas, history, and workspace interface

- For website projects, the canvas top bar includes **Fit**, **Desktop 1440**,
  **Tablet 768**, and **Phone 390** width presets to test responsive layouts
  before you export. Slide decks, graphics, and logos retain their fixed
  artboard dimensions.
- Save history and the current source comparison display retained before and
  after entrypoint thumbnails next to the changed-file list and text changes.
  When a snapshot has expired, is missing, or was refused, BurnGuard shows an
  explicit fallback message instead of showing the live canvas.
- The unverified draft banner states that a recovered draft stays unverified
  until a full design review passes. The photo placements panel states that
  reference photo delivery to image generation is self-reported by the AI tool
  and is not verified independently by the app.
- Clearer focus outlines, disabled button states, loading and empty states,
  tooltips, and better text and control contrast apply across light and dark
  themes. The project header and canvas toolbar remain on one row and move
  extra controls into **More** menus on narrow screens. Canvas mode panels
  open as a bottom sheet (up to 65% height) on narrow viewports, and unknown
  routes or missing project IDs display dedicated not-found pages.

## Export, print check, and local files

- Selecting **Export** shows the available formats and provides separate dialogs
  for **Export settings**, **Print check**, and **Recent exports**. Platform
  installation guides open inside the dialog as a step view with a **Back**
  button, and closing any export dialog returns focus to the **Export** button
  while keeping the page interactive.
- **Print check** evaluates inline and stylesheet CSS `background-image` URLs
  (including layered and print-only backgrounds) at their rendered
  `background-size` tile dimensions. The dialog also states that prior
  upscaling of source files is not detected.
- If the bundled browser executable is absent, BurnGuard falls back to an
  installed system browser for rendering and checks.
- **Open project folder** in the project top bar (or inside **More** on
  narrow viewports) opens the project's local directory under `~/.burnguard` in
  Finder, File Explorer, or your system file manager.
- In a source checkout, running `bun scripts/burnguard-read.ts projects` or
  `bun scripts/burnguard-read.ts project <id> [--json]` opens the local profile
  database read-only and outputs active projects or a Markdown brief (project
  directory, entrypoint, project instructions, design-system tokens and rules,
  and up to 2,000 files) so a coding agent can inspect a live project while
  BurnGuard is open.
- Added the [user guide](https://github.com/ashmoonori-afk/BurnGuard/blob/main/doc/user-guide.md) with step-by-step instructions for
  creating a first website, running image-only edits, transferring a project
  via a `.burnguard-project` backup, and locating local profile files.

## Reliability

- If BurnGuard quits unexpectedly during a generation, the next start stops
  the AI tool process that was still running before it restores project files,
  so a leftover process cannot keep writing into the project. Startup stops
  with an error if it cannot confirm the process has stopped.

## Installation

Use the Windows x64 installer or portable ZIP, or the macOS arm64 installer
or portable ZIP. Extract portable packages completely before opening them.
Packages remain unsigned: Windows may require **More info → Run anyway**;
macOS may require **System Settings → Privacy & Security → Open Anyway**.
Verify downloads against the platform-specific SHA-256 files.
