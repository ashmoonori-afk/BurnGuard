**直接连接你已在使用的 Claude Code 或 Codex 的开源本地设计工作空间。**

## 从设计方向开始

选择项目格式，写下你的创意，并按需选用一个已注册的设计系统。BurnGuard 会根据创意自动建议可修改的项目名称，受众字段为可选项，内联展示最多 4 个设计系统推荐，并将详细需求设置收在**高级设置**中。点击**创建并生成**即可一步完成项目创建并发送首条请求。全新安装首次启动时，首页会显示可关闭的首次运行引导卡片，检查 Claude Code 和 Codex 连接状态，并支持直接在卡片中创建并生成第一个网站项目。你也可以不使用设计系统直接开始。

内置目录包含 **43 个主题**，其中 **33 个为原创主题**。每个主题除了字体排印和颜色令牌外，还配有导航、首屏与页脚布局规则。原创示例系统和提示词预设同样包含布局规则。你可以从受支持的文档、网站、Git 仓库、Figma 文件或单个 `DESIGN.md` Markdown 文件导入自己的设计系统，审核并发布后用于项目。任何已注册的设计系统或内置主题都可以下载为单个 `DESIGN.md` 文件；每个系统最多可保存 60 条明确的**要做（Do）**和**不要做（Don't）**规则，并在每次使用该系统生成时自动传入。[浏览 43 个内置布局](<design system themes/>)

*带有格式标签、设计系统搜索和刷新按钮的新建项目对话框。你可以选择已注册的设计系统或内置主题，也可以不使用设计系统直接开始。*

打开任意系统的概览即可查看其导航、首屏和页脚规则。**方向预览与完整生成使用同一套布局规则**（包括精简模式）：三个方向预览会在所选系统的结构下调整核心信息、依据和行动号召的侧重点。方向预览展示结构摘要，实际渲染的页面则包含更完整的细节。如果在选择系统前或更新系统规则前保存过方向，可以基于当前系统重新生成。

## 一个工作空间，多种交付产出

| 制作类型 | 工作内容 | 导出与交付 |
|---|---|---|
| 网站 | 相互链接的多页面、共享样式表、图片与可复用区块 | HTML、CSS、JS 与素材 ZIP，或发布到你的 Vercel 账号 |
| 幻灯片 | 幻灯片预览、字体排印、演示模式与评论 | HTML、PDF 或 PPTX |
| 平面图形 | 自定义画板尺寸、海报与多画帧组合 | PNG、PNG 合集或 PDF |
| 标志（Logo） | 多轮方案探索并选定一个母版 | 母版 SVG¹、品牌规范 PDF 或 HTML 归档 |
| 商品详情页 | 带分区图片的长竖版页面 | 按区块边界切分的 PNG 或 JPEG 切片 |
| 平台页面 | Cafe24 Smart Design 或 Imweb 代码组件包 | 附分步手动安装指南的导出包 |

¹ 母版 SVG 导出仅适用于标志项目。

![BurnGuard 幻灯片编辑器，显示带演示和导出控件的 SONNEL 幻灯片](doc/images/readme-slide-workspace.png)

*使用同一工作空间编辑幻灯片，顶栏带有演示与导出控件。*

## 在预览画面上直接修改

- **在画布上直接编辑。** 点击元素即可修改文字、链接、图片地址、尺寸、旋转角度、字体排印、间距或颜色。网站项目在画布顶栏提供**适应**、**桌面 1440**、**平板 768** 和**手机 390** 视口宽度按钮，便于在导出前检查响应式布局。保存历史、修订前后的入口缩略图对比和撤销功能可随时回到早期版本。
- **固定评论或保存为长期规则。** 点击画布可在元素上添加评论标记并发送 AI 修改请求。标记会随页面滚动保持在元素上，点击已保存的标记可重新打开评论。将鼠标悬停在画布上，在 Windows 和 Linux 上按 **Alt+C**、在 macOS 上按 **Option+C** 可打开快速评论。在对话中，对首次需求说明之后的任意跟进消息点击**保存为规则**，即可将修改整理为设计系统的“要做”或“不要做”规则，或添加到项目指引中。点击项目顶栏的**项目指引**可编辑随每次请求发送的长期说明（最多 4,000 个字符）。
- **添加参考文件。** 附加受支持的 PDF、PPTX、DOCX、图片或文本文件，或导入导出的 HTML 项目 ZIP 及 `.burnguard-project` 备份。上传的原文件与发布的网站素材分开保存。
- **导出前进行质量检查。** 质量检查和 UX 诊断面板会检查布局、对比度、链接与文案，并可向 AI 发送修复请求。检查结果仅供参考，导出或发布前请自行核对渲染画面。

导出菜单中的**印刷检查**对话框会按打印尺寸计算图片分辨率，低于 300 ppi 提示警告，低于 150 ppi 提示强警告。它会测量 `<img>` 元素裁剪后保留的原始像素，并按实际渲染的 `background-size` 平铺尺寸测量行内样式和样式表中的 CSS `background-image` 地址（包括多层背景和仅打印背景）。该检查无法检测源图片在加入项目前是否已被放大。

### 图片、图表与 3D

为每张图片指定明确的用途，例如产品主图、活动场景、说明插画或背景。BurnGuard 提供跨 13 个领域的 **21 种图片处理风格**和 **38 个用途配方**。生成图片**默认为写实摄影**：除非明确要求，否则不生成抽象图像；图片提示词按摄影拍摄说明编写；塑料感皮肤、发光背景和乱码文字等常见生成瑕疵会在检查阶段被拦截。非摄影风格仅在你选择或要求时使用。需要生成新图片的任务要求所连接的服务商支持图像生成，平面图形和标志生成则需要已登录的 Codex 连接。[图片制作指南](doc/image-production.md)

## 开始使用

1. **安装。** 从 [GitHub Releases](https://github.com/ashmoonori-afk/BurnGuard/releases/latest) 下载 Windows 或 macOS 安装程序或便携版 ZIP。在 Windows 上，运行安装程序，或完整解压便携版 ZIP 后打开 `BurnGuard.exe`。在 macOS 上，运行安装程序，或将便携版应用移入“应用程序”文件夹。发布安装包目前未签名。
   - **macOS：** Gatekeeper 会拦截首次启动。请先尝试打开一次应用，然后前往**系统设置 > 隐私与安全性 > 仍要打开**。也可以在终端运行 `xattr -dr com.apple.quarantine "/Applications/BurnGuard.app"`。在 macOS 15 及更高版本上，按住 Control 点击应用已无法绕过 Gatekeeper，请使用系统设置路径。
   - **Windows：** 打开未签名的安装程序或可执行文件时，SmartScreen 可能显示“Windows 已保护你的电脑”。点击**更多信息**，再点击**仍要运行**。
2. **试用示例。** 在连接 AI 工具前，可以先打开内置示例项目体验画布，或点击任意示例卡片上的**查看此示例的需求说明**和**从此示例开始**。
3. **连接 CLI。** 安装并登录 Claude Code 或 Codex CLI，然后在设置中选择工具和模型。**默认启用 vanilla 模式；当模型支持时，推理强度默认为 medium（中等）。** 若不支持 medium，BurnGuard 会选择第一个支持的推理强度；缺少强度信息时使用 low（低）。Vanilla 模式会忽略个人 CLI 插件和全局指令，仅保留 BurnGuard 的项目上下文。
   - **Codex 进度信号（默认开启）：** BurnGuard 会在这台电脑本地接收 Codex 使用指标，避免编写大型 HTML 页面等长时间无输出的步骤被误判为卡死。你可以在设置中关闭**检测 Codex 是否仍在工作**。如果你已为 Codex 配置了自己的 OpenTelemetry 收集器，此开关会保持关闭，直到你手动开启，因为本地信号开启期间 Codex 指标不会发往外部收集器。
4. **创建项目。** 输入你的创意，按需选择设计系统，点击**创建并生成**即可一步创建项目并启动首次生成。
5. **导出或发布。** 在**导出**中下载独立文件，点击项目顶栏的**打开项目文件夹**在文件管理器中查看本地文件，或选择**分享 → 准备当前作品 → 公开发布**，使用已保存的 Vercel 令牌部署网站。

| 要求 | 详细说明 |
|---|---|
| Windows 桌面端 | Windows 10/11 x64、.NET Framework 4.8 和 WebView2 Runtime |
| macOS 桌面端 | 搭载 Apple 芯片的 macOS 14 及更高版本 |
| AI 生成 | 已安装并登录的 `claude` 或 `codex` CLI 及对应服务商账号 |
| 渲染与导出 | 受支持的本地 Chromium 内核浏览器；状态在设置中显示 |
| 应用更新 | Windows 与 macOS 发布源；替换安装包时请保留本地配置文件夹 |

公开发布网站需要你的个人 Vercel 令牌和可选的团队 ID。粘贴在分享对话框中的令牌仅在该次发布期间保留在内存中；保存在设置中的令牌仅存放在这台电脑的本地配置文件中。托管额度与访客访问权限遵循你的 Vercel 账号设置。Cafe24 和 Imweb 导出包需要手动上传，尚未在真实营业的客户店铺中验证。

## 你的项目保存在本地

BurnGuard 将 SQLite 数据库、项目、设置、设计系统和导出缓存保存在 `~/.burnguard`（Windows 上为 `%USERPROFILE%\.burnguard`）。升级应用时请保留此文件夹。在任何打开的项目中点击**打开项目文件夹**，即可在 Finder、文件资源管理器或系统文件管理器中打开对应目录。

执行生成时，所选项目上下文会发送给你配置的 AI 服务商。通过 URL 导入或发布网站也会使用网络。本地后端仅监听 `127.0.0.1`，在每次请求时校验启动授权，并在沙盒 iframe 内渲染项目页面。[安全模型](doc/01-architecture.md#7-security-and-safety-model)

## 从源码运行

请使用与 CI 固定版本一致的 **Bun 1.3.14**。

```sh
git clone https://github.com/ashmoonori-afk/BurnGuard.git
cd BurnGuard
bun install --frozen-lockfile
bun run scripts/dev-launcher.ts
```

启动器会在 `http://127.0.0.1:5173` 启动前端，在 `http://127.0.0.1:14070` 启动后端。按 Ctrl+C 停止服务。在 macOS 上，可在 Finder 中双击 `Start-BurnGuard.command` 启动同一套开发服务（需要 Bun），关闭终端窗口即停止服务。在 Windows 上，`Start-BurnGuard.bat` 用于开发环境下从源码构建并启动桌面端外壳（需要 Bun 和 .NET 8 SDK），修改源码后请传入 `--rebuild`。普通用户请从 GitHub Releases 下载安装包，不要使用源码启动器。

如需直接浏览仓库中的内置主题页面，请在浏览器中打开 `design system themes/previews/index.html`。这些页面使用仓库内的本地字体和插画。修改主题令牌后，请重新构建令牌目录和网站预览：

```sh
bun run catalogue
bun run previews
```

`previews` 会复用已提交的插画重新生成 HTML 文件，不会调用图像生成服务。之后如需重新截取网站缩略图，请在已安装 Node.js 和本地 Chromium 内核浏览器的电脑上运行 `bun run previews:thumbnails`。

```sh
bun run typecheck
bun run check:whitespace
bun run build:frontend
node packages/backend/node_modules/playwright-core/cli.js install chromium
bun test
```

请在仓库根目录运行测试，以便测试 preload 创建隔离的临时配置目录。浏览器测试需要 Node.js；执行 `bun install` 后请运行上面的命令安装 Playwright 浏览器构建。当该构建未安装时，浏览器桥接会按与就绪探测相同的顺序回退到系统已安装的浏览器通道。浏览器 QA 需要 Node.js 和本地 Chromium 内核浏览器；在 Windows 运行器上可能需要传入 `bun.exe` 的完整路径。[贡献与原生构建](doc/CONTRIBUTING.md)

### 从编码代理读取项目

无需导出和重新导入文件，你的编码代理即可直接读取正在运行的 BurnGuard 项目。在源码检出目录中运行：

```bash
bun scripts/burnguard-read.ts projects                 # 列出活动项目：id、类型、名称、设计系统
bun scripts/burnguard-read.ts project <id>             # 输出 Markdown 摘要：目录、项目指引、设计系统规则、文件列表
bun scripts/burnguard-read.ts project <id> --json
```

该命令以只读模式打开 `BG_APP_ROOT`（默认 `~/.burnguard`）中的配置数据库，不向磁盘写入任何内容，也不打开网络端口，因此在 BurnGuard 运行期间也可安全调用。

- 创建项目从输入创意开始，自动建议可修改的项目名称，受众字段改为可选，点击**创建并生成**即可立即发送首条请求（若发送失败，会在输入框中保留草稿）。全新安装首次启动时，首页会显示可关闭的首次运行卡片来检查 Claude Code 与 Codex 连接，全部 15 张内置示例卡片均支持查看韩语、英语或简体中文需求说明并直接用其创建新项目。
- 设计系统最多可保存 60 条**要做（Do）**和**不要做（Don't）**规则（每条最多 280 个字符）并在每次生成时传入；包括内置主题在内的任何已注册设计系统均可下载为单个 `DESIGN.md` 文件或从 `.md` 文件导入。当已保存的规则列表损坏时，生成和系统视图会保留有效规则并跳过损坏项，编辑规则时则拒绝覆盖已损坏的列表。
- 每个项目都提供随每次请求发送的**项目指引**对话框（最多 4,000 个字符，包含在 `.burnguard-project` 备份中）。对话中的跟进消息提供**保存为规则**按钮，可将修改整理为设计系统的“要做”或“不要做”规则，或加入项目指引。
- 网站项目在画布顶栏提供**适应**、**桌面 1440**、**平板 768** 和**手机 390** 预览宽度按钮。保存历史和当前源码对比会在变更文件列表旁显示保留的修改前后缩略图，并在快照不可用时显示清晰的占位说明。
- 点击项目顶栏的**打开项目文件夹**即可在 Finder、文件资源管理器或系统文件管理器中打开项目的本地文件夹。在源码检出目录中运行 `bun scripts/burnguard-read.ts` 可只读打开本地配置数据库，让编码代理在 BurnGuard 运行期间列出活动项目或输出项目的摘要、项目指引、设计系统规则和文件列表。
- **印刷检查**会按实际渲染的平铺尺寸测量行内样式和样式表中的 CSS `background-image` 地址，并说明无法检测源文件此前是否被放大；当内置浏览器缺失时，BurnGuard 会回退使用系统已安装的浏览器。若 BurnGuard 在生成过程中意外退出，下次启动时会在恢复项目文件前先停止仍在运行的 AI 工具进程（若无法确认该进程已停止，启动会报错中止）。
- 浅色与深色主题具备更清晰的焦点轮廓、加载与空状态界面、工具提示以及更高的文字和控件对比度；项目顶栏与画布工具栏保持单行显示，在窄屏下通过**更多**菜单收纳操作并以底部抽屉打开模式面板。导出菜单将**导出设置**、**印刷检查**和**最近导出**放入独立对话框，在对话框内分步显示平台安装指南，文档新增了 `doc/user-guide.md` 与 `Start-BurnGuard.command` 说明。

### 0.5.30

- 因设计检查未通过而被拒绝的生成结果，可以作为单独的未验证草稿打开；原项目、修订版本和检查记录保持不变，草稿在当前内容通过此前未完成的全部检查项之前会一直标为未验证。已过期、已损坏或包含不允许发布文件的结果会给出明确原因并拒绝打开。
- 修改请求可以限制为仅改文字或仅改图片，还可指定页面、画板或元素。发布前，BurnGuard 会把结果与上一修订版本对比（文字、图片引用、包括与 CSS 背景共用图片在内的文件字节、样式、脚本、结构以及会改变显示效果的空白字符），超出范围的改动不会发布。历史记录会列出变更页面、变更类型和修改前后的文字；这是源码对比，不是像素对比。
- 导出菜单新增印刷检查：检查页面尺寸、缺失或远程加载的字体、浏览器就绪状态，以及每张图片裁剪后的有效分辨率（低于 300 ppi 警告，低于 150 ppi 强警告，仅测量 `<img>` 元素的原始像素）。每个导出步骤都有独立的时间限制，卡住或失败的步骤会附带恢复操作说明。
- 键盘聚焦时才显示的跳过导航链接不再被误报为文字溢出；没有元素 ID 的问题项会显示选择器和位置。
- 真实物体的照片可附带放置记录（带来源的参考照片、尺寸比例、由代理解释的参考照片是否送达生成器、候选对比、仅裁剪放置），只有记录完整时才显示为“参考已验证”。被拉伸的照片以及混入发布文件的参考照片会被列为必须修复的问题。
- 修复了 Windows 上浏览器冷启动较慢时浏览器检查中途失败的问题。

### 0.5.29

- 检查点快照发布时带有完整性清单和持久化写入；中断的替换会恢复上一组已验证的快照对，未完成的新快照会被拒绝，而不会被当作旧版数据处理。
- 作品发布和回滚在提交前会先刷写持久化状态，设计令牌和字体 CSS 更新采用原子替换。已删除的项目在保留期内可从“最近删除”恢复。
- 数据库迁移会备份现有数据库、拒绝未知的新版结构并检查外键完整性；CI 会拒绝改变已发布迁移顺序的迁移文件。
- 导出发布再次校验已验证归档的摘要和大小限制；损坏的检查点回执不再阻止导出项目备份包。
- 服务商标准输出解析增加了上限，取消测试在 Windows 和 POSIX 上均覆盖子进程和分离的后代进程。Codex 图片通知不再依赖带线程 ID 的文件名提示，扫描器仍会验证并选出当前线程的文件。
- 项目监视器会合并突发事件并在关闭时干净退出，浏览器启动与清理会等待传输结束并限制资源生命周期。
- macOS 可从登录 shell 和 Node 版本管理器路径查找服务商 CLI，并将更新缓存清理与下载准入串行化。原生关闭与更新对话框已本地化，生成过程中关闭应用会请求确认，批注草稿在重新打开后仍会保留。
- 快速批注使用 Alt/Option+C，两个历史记录处理器均支持 Ctrl+Y，CLI 探测失败会显示单独的说明与恢复指引。超出大小限制的导入会显示支持的上限并保留已填写的值。
- 本地引导需要启动器持有的授权；仅凭 Origin 请求头无法获取访问能力。带令牌的 Figma 请求拒绝重定向，SVG 方向预览带有保护性原始文件响应头，归档解压使用路径边界解析器。
- 服务商日志和完成消息不再包含私有暂存路径。Ubuntu CI 运行所有发现的测试文件，无基线排除项，包含浏览器一致性与 PDF/PNG/PPTX 冒烟测试；监视器与图片回归测试也同时在 macOS 和 Windows 上运行。

### 0.5.28

- 基于提取的设计系统新建网站项目时，现在从基于 class 的页面骨架开始，保留提取的首屏图片，并为按钮、副标题和页脚文字使用易读的颜色。已编辑过的页面不会被起始模板替换。
- 质量检查会把每个分区与参考截图对比，并裁出最薄弱的分区，因此一次修复只处理一个分区。每张参考截图旁都会保存一张区块轮廓图。
- 网站提取更准确：副标题、品牌名、颜色令牌和首屏图片的测量更可靠，抓取的 SVG 图片会被清理，样式表重定向必须停留在同一站点内，无法测量布局时会记录原因。
- 未安装任何 AI 工具时，发送按钮会被禁用，并显示原因和设置链接。被停止或失败的轮次现在总会显示为已停止或失败；在另一条消息运行时发送的消息会被干净地拒绝，不再留下只记录了一半的轮次。
- BurnGuard 在后台重启时，已打开的窗口会提示并提供重新加载。在手机宽度下，工作区、画布工具和导出仍可使用。
- 在模型支持的情况下，推理强度默认为 medium；受支持的模型列表使用当前官方模型 ID。
- 画布只加载页面用到的字体，并在页面绘制完成前显示渲染状态。样式侧边编辑器会保留你输入的值。
- 导出处理超大或特殊的项目文件时更快更安全，保留 macOS 带重音符号的文件名，并正确编码下载文件名。
- 错误信息不再显示私有文件路径或原始系统错误文本，设置中的错误会说明如何恢复，韩语和中文文案也已补全。
- macOS 应用遵循与 Windows 应用相同的桌面规则，更新检查会正确排序预发布版本。

### 0.5.27

- 项目可以导出为可移植的 `.burnguard-project` 包，并在另一台电脑上恢复。已保存的服务商和访问令牌以及本地配置不会包含在内，恢复时总是创建一个新项目。
- 交接导出新增机器可读的清单、`HANDOFF.md` 和给编码 CLI 的提示词，并附带可复制的命令，用于在 Claude Code 或 Codex 中继续工作。
- 设置 > 运行时诊断会列出每个 CLI 连接的版本和能力，以及最近的生成在哪个阶段停止；失败或中断的项目可以从已保存的文件继续。
- 视觉质量指引现在覆盖网站、幻灯片、图形、Logo 和图示。质量面板新增了仅供参考的检查：分隔破折号、占位文案、眉标（eyebrow）标签、重复或换行的主要行动号召、强调色和圆角数量、重复的相邻分区；并为网站新增渲染后的用户路径检查：无处可去的链接、横向滚动的移动端导航、不可见的键盘焦点，以及加载时的布局偏移。
- 支持 GIF 附件，元数据中嵌入 SVG 文本的图片现在也能解码。WebP 文件在解码前先验证，不可信图片的颜色采样在单独的进程中运行。
- 可为一个设计生成两到四个视觉备选方案，并排比较，选定一个并删除其余的。
- PDF、PNG、PNG ZIP 和 PPTX 导出会显示与画布的逐页相似度分数。该检查只会警告，不会阻止下载。
- 可以导入 Figma JSON 导出（可附带画框图片），作为与你的设计系统令牌匹配的不可变参考。无需 Figma 账号令牌。
- 网站设计系统按页面提取（导航、页脚和站点地图，遵守 robots.txt），包含测量的布局、页面颜色、字体角色、资源使用规则和资源提示词。有本地无头浏览器时，最多四个源页面会离线渲染并在桌面和移动宽度下测量，这些页面的参考截图会随系统一并保存。
- 使用提取系统生成网站时，测量值会作为硬性约束，连同起始样式表和页面骨架、作为视觉目标的参考截图以及一条明确的优先级规则一起提供；检查会对照测量的布局审查页面，并修复一次。
- 生成指引按模型家族的能力档案（claude-frontier、gpt-image、standard）执行。使用 Claude Opus 或 Sonnet 时，若未提供 Logo，BurnGuard 会依据你的令牌按七条构造规则设计 CSS 与 SVG Logo，并从开放素材目录（无需密钥）查找开放授权的照片、插图和图标来代替生成图片，保存每个文件时附上来源和许可证。Codex 上支持图像生成的模型仍然自行生成图片。网页搜索可在设置中关闭，模型选择器会推荐 medium 或更高的推理强度。
- 生成和修复提示词带有证据规则：视觉方面的结论只能来自渲染证据，没有运行的检查要报告为未验证，不得使用未经测量的数字。
- 首次运行时，应用会跟随系统语言（韩语、简体中文，其他情况为英语）；在设置中选择的语言始终优先。首次成功导出或发布后，应用会询问一次是否给 GitHub 点 Star；不会向任何地方发送任何内容。

### 0.5.26

- Vercel 令牌可保存在这台电脑上，发布只需一次点击。设置中只显示令牌是否已保存，从不显示令牌本身。

- macOS 发布冒烟测试改为通过图标而不是工具栏位置找到画布的“编辑”控件，与 0.5.25 中去掉“选择”模式的工具栏保持一致。

### 0.5.25

- 即使渲染后的设计检查无法运行（缺少浏览器，或大型网站超时），生成轮次也会提交；聊天中会显示“检查未完成”徽标，而不是拒绝该轮次。必须修复的问题只会在该轮次改动过的页面中阻止提交；修改了共享 CSS、脚本或图片的轮次会检查所有页面。
- 质量面板把不适用于幻灯片和固定尺寸图形的检查报告为不适用，可测量纯渐变上的对比度，把等宽文字视为独立的字体角色，扫描链接的样式表中硬编码的颜色，并标出导出无法获取的远程字体、图片和框架。
- 设计需求说明会带上应用语言；UX 检查结果、质量与平台修复请求、方向预览以及应用构造的每个 AI 请求，都以韩语、英语或中文显示；每个服务器错误码都有对应的错误信息。
- 提示词框架理顺了相互矛盾的规则（图表、配色、断点、社会认同、地图嵌入、仅限 Windows 的 PowerShell），新增了韩文字体排印规则，在每个项目内放入内置图标参考，按请求控制 3D 与图表约定，提供完整的设计系统令牌块，并在精简模式下削减固定规则。
- 画布：编辑面板可编辑图片来源和链接目标，已解决的批注可以重新打开，新批注会打开其编辑器，Ctrl/⌘+Z 可撤销样式调整，色板来自页面自身的令牌，列出所有内置字体，并移除了重复的“选择”模式。
- 首页与设置：深色模式在所有界面生效，语言点击即保存，后端检测失败时显示重试，创建成功后清空创建草稿，搜索覆盖所有项目。
- 网站导入会剥离脚本和表单，而不是拒绝该页面；在提取的令牌上记录媒体查询上下文，并输出规范的令牌约定；起始模板声明 `--page-background`。

### 0.5.24

- 新项目和预置示例重新可以在画布、实时预览和演示中加载；此前内置字体数量超出了画布的字体上限。
- PDF 和 PNG ZIP 导出会保留作者编写的 grid/flex 布局和页面背景，等待懒加载图片，并把预置示例图形导出为画板 PDF。过大而无法导出 PDF 的幻灯片会在渲染前被拒绝，并给出明确原因。
- Cafe24 和 Imweb 包接受普通链接，包含每个页面以及仅子页面使用的资源，页脚脚本保持可用，附带字体许可证，并且不再需要无头浏览器。
- 导出只包含文档用到的内置字体，ZIP 文件带本地时间戳，已删除的项目不再留下缓存的导出。
- 聊天会报告该轮次的工作是否真正进入了项目，包括失败的幻灯片检查和修复；按要求可让附加的源页面与幻灯片一一对应。
- macOS 应用：能找到通过 Homebrew 或在 `~/.local/bin` 中安装的 CLI 和 Python，并读取登录 shell 的 PATH 来查找通过 nvm、Volta、fnm 或自定义 npm prefix 安装的 npm CLI。在浏览器中打开外部链接，支持标准的 ⌘C/⌘V/⌘Q 快捷键，替换已有的下载，并在退出前等待本地服务器停止。
- Windows 应用：遇到可恢复的 WebView2 进程故障时保持打开，并列出已安装的字体。Linux 源码运行也会列出已安装的字体，在 macOS 和 Linux 上每个配置文件现在只由一个后端拥有。
- 设置拆分为共享配置文件，以及设备本地的凭据和策略。
