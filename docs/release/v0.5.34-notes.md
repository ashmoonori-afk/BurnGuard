# BurnGuard v0.5.34

BurnGuard v0.5.34 refreshes project design-system baseline candidates right
after you save a color token or upload a role-assigned font, adds experimental
deterministic PNG-to-SVG tracing before AI finalization in logo projects, and
updates Hono and Vite to address six dependency security advisories.

## Design-system baseline checks

- Saving a color token in a design system now refreshes any open project's
  baseline candidate check immediately (`GET
  /api/projects/:id/design-system-pin`) instead of waiting for a page reload.
  Uploading a font refreshes the baseline candidate only when the upload
  assigns a font role (`display`, `sans`, `serif`, or `mono`) on a design
  system that has a `tokens_css_path` token stylesheet
  (`colors_and_type.css`).
- When the refreshed candidate differs from the project's pinned baseline, the
  project banner shows **Changes in the new baseline · Color and type tokens**
  and the **Apply new baseline to this project** button right away. The
  project's pinned digest and revision stay unchanged until you explicitly
  click **Apply new baseline to this project**, and a rejected save or failed
  candidate refresh leaves the pinned baseline untouched.

## Experimental deterministic PNG logo tracing

- When you finalize a selected logo candidate
  (`explorations/round-N/candidate-M.png`), BurnGuard verifies the selected
  PNG's SHA-256 digest and runs an in-process TypeScript tracer before starting
  the AI turn. It decodes the PNG after keeping only pixel, transparency, and
  color-management chunks, fits a deterministic RGB palette of up to 8 colors,
  coalesces fitted colors within squared RGB distance `3 * 16^2` (`768`),
  merges 4-connected speckles smaller than 4 pixels into the nearest bordering
  region, walks 4-connected lattice edges, simplifies contours with
  Douglas-Peucker tolerance `max(0.75, max(width, height) / 640)`, and writes a
  validated compound-path `logo.svg` with `fill-rule="evenodd"` beside the
  recorded selection in `explorations/manifest.json`.
- For fully opaque inputs (`alpha >= 128` on every pixel), the largest palette
  region is painted first as a full-canvas background rectangle so subpixel
  contours discarded during simplification reveal the background color rather
  than transparency. Inputs with transparent pixels and binary-mode traces keep
  transparent backgrounds.
- When tracing succeeds within the 4-megapixel (`4,194,304` pixels),
  250,000-edge, 2,000,000-distance-evaluation, and 1 MiB (`1,048,576` bytes)
  budgets, the AI turn receives `<burnguard-logo-trace-v1>` with `status:
  "ready"` and writes the brand guidelines (`index.html`) while leaving
  `logo.svg` and `explorations/manifest.json` untouched unless you explicitly
  ask for vector tidy-up. If the image exceeds a tracer budget or cannot be
  traced, BurnGuard passes `status: "fallback"` and uses the existing AI
  vectorization path.
- Measured on the 18 SHA-locked logo and mark fixtures (8 logo candidates, 4
  illustrations, and 6 synthetic 128x128 marks, tested on 2026-10-23 with 3
  measured repeats after 1 warm-up), total SVG output dropped from 2,093,464
  bytes in round 1 to 41,656 bytes in round 2 (98.01% smaller, and 62.68%
  smaller than the 111,615-byte 8-color polygon reference run on the same 18
  inputs), with 18/18 passing `validateLogoSvg`, mean foreground IoU 0.9881,
  and mean RGB MAE 1.0356/255 composited on white. Palette coalescing, alpha
  thresholding, and polygon simplification are lossy, so close color steps,
  gradients, translucent edges, and tiny details can be simplified or merged,
  and curved contours can remain angular unless you ask for tidy-up.
- Added MIT, Apache-2.0, and BSD-2-Clause attributions for the adapted tracing
  and polygon-reduction algorithms (`vtracer`, `visioncortex`, and
  `simplify-js`) in `NOTICE` and `THIRD_PARTY_NOTICES.md`, and included
  `THIRD_PARTY_NOTICES.md` in packaged runtime builds.

## Security

- Updated backend `hono` from `4.13.7` to `4.13.13` and frontend `vite` from
  `6.4.3` to `6.4.5` in the workspace manifests and `bun.lock`, resolving six
  security audit advisories that are now gone from `bun audit` (five unrelated
  advisories remain on the existing allowlist).
- Hono `GHSA-5r4p-p66f-jhc7` fixes a double path decoding flaw in
  `serveStatic` where a second decode after router matching could allow a
  crafted percent-encoded request path to bypass route middleware mounted on a
  static prefix.
- Vite `GHSA-9jrq-w75r-8gcw` and `GHSA-rq7h-c2jc-7f22`, plus
  `launch-editor` `GHSA-698v-4r3x-3vcv`, `GHSA-r825-w8mm-5pxw`, and
  `GHSA-587h-7wmj-h5pm`, fix dev-server script loading and `server.fs` path
  checks in Vite, and Windows argument escaping, leading-flag handling, and
  `..:line:column` existence-check bypasses in `launch-editor`.

## Installation

Use the Windows x64 installer or portable ZIP, or the macOS arm64 installer
or portable ZIP. Extract portable packages completely before opening them.
Packages remain unsigned: Windows may require **More info → Run anyway**;
macOS may require **System Settings → Privacy & Security → Open Anyway**.
Verify downloads against the platform-specific SHA-256 files.
