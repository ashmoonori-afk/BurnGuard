# Generation, edit, and export logic — before and after (2026-09-10)

This document compares the deliverable **generation**, **edit**, and **export** logic of BurnGuard at two commits, as a 기존안 (before) versus 개선안 (after) table per area. It records what the code does, not what any plan intended.

| | Commit | Meaning |
|---|---|---|
| 기존안 (before) | `0641552` — "chore: prepare 0.5.4 release from latest main (#33)" | The base doc/14 was written against; last main commit before the doc/14 implementation |
| 개선안 (after) | `01c42be` — merge of PR #47, `origin/main` at the time of writing; `package.json` version 0.5.9 | PRs #35–#47: Vercel user choice and `skip_quality_check` (#35), privacy preview and macOS fixes (#36), releases 0.5.6 to 0.5.9 (#37, #41, #44, #46), seed security fix (#38), Vercel public-file filtering and alias (#39), doc/14 implementation (#40), attachments and artboards (#42), untracking `.omo/`, `devplan/`, `ref/` (#43), project import (#45), live previews and deck copy review (#46), image uniqueness and artboard verification (#47) |

Reading assumption: "before" is the state before the doc/14 work landed and "after" is the latest `origin/main`. Rows that say **absent** on the before side describe capabilities that did not exist at `0641552`. Every path in the Evidence column is repository-relative and was checked to exist at `01c42be`. Symbol names in the Evidence column are the functions, types, or constants that implement the row.

Sources: three read-only code comparisons of the two commits (one per area), `doc/14-deliverables-and-platform-publishing-plan-2026-09-09.md`, `doc/15-platform-packages-and-graphic-sets-2026-09-10.md`, and ADR-015 in `doc/07-decisions.md`.

## 1. Summary

- Generation gained a versioned graphic-set block (six kinds, 1–40 frames, platform presets, a seven-field product-detail brief), a bounded multi-page brief and site map in the prompt, an active-page target for each turn, wider attachment intake (Word and images), and a live preview stream with DOM feedback during the turn. `ProjectType` did not change.
- Editing gained multi-page navigation inside the sandboxed canvas, frame navigation with a 9:16 safe zone, cursor-anchored zoom, a site-wide design audit with shared-block consistency checks (all advisory), an idle quality-panel state, AI repair requests from export findings, and import of previously exported HTML projects.
- Export grew from five formats to eight (`png_zip`, `cafe24_package`, `imweb_package`), added artboard PDFs, section-aware slicing with JPEG validation, a single Chromium capture seam, platform lint with one blocking rule, typed export errors, persisted findings on the attempt, and an install-guide surface. Vercel publishing now filters non-public files instead of refusing and prefers the stable alias.

## 5. Remaining gaps

Recorded in `doc/15-platform-packages-and-graphic-sets-2026-09-10.md` ("Blocked by environment and deferred") and still true at `01c42be` unless noted:

- **Platform validation (T33, T61).** No real Cafe24 shop or Imweb site was available; every package is documentation-tested only. Uploader behaviour, WOFF2 acceptance, URL patterns, charset handling, widget script survival, and published rendering are unverified.
- **Imweb Google Fonts opt-in.** ADR-015 permits a guide-flagged opt-in and the guide text describes it, but `ExportOptions` has no such field and `common/header-code.html` never emits a Google Fonts link. Only the system-font fallback ships.
- **Per-frame export progress.** `ExportProgress` stays the fixed six-step lifecycle; a batch does not stream per-frame or per-slice progress.
- **`png_zip` at DPR 2.** Not supported; batches render at DPR 1.
- **Frame and slice counts in the status row.** `ExportJob` carries no frame or slice count.
- **Finding severity is client-derived.** The backend reports `{ code, path }`; severity and Korean copy live in `packages/frontend/src/components/export/export-delivery.ts`, so a new backend code with no client entry falls back to a generic warning.
- **Declared but never emitted lint codes.** `platform_missing_asset`, `platform_invalid_markup`, `platform_unresolved_destination` exist in the union but those conditions fail hard as `ExportError` or `ExportPackageError` before lint runs.
- **Per-output receipt writer.** `packages/backend/src/services/exports.ts` passes a no-op `receiptWriter` into the batch and package renderers; receipt shapes are validated but the per-frame write-back does nothing.
- **Platform export branch has typecheck coverage only.** `renderPlatformPackage` and the `exports.ts` platform branch are not exercised by an automated test; `buildPlatformPackage` is.
- **Label wording.** doc/14 T06 chose "이미지 묶음 (ZIP)" for `png_zip` including JPEG slices; the shipped label is "PNG 묶음 (ZIP)" in every case.
- **Samples (T62).** No multi-page website sample and no card-news, banner, or product-detail example collection were added under `samples/`.
- **Deferred by decision (T66).** Direct authenticated push to Cafe24 or Imweb, WebP, MP4 and GIF, CMYK or PDF/X, automatic WOFF conversion, arbitrary page rename or move, and any new hosting or credential infrastructure.
- **Deck copy review is advisory only.** The `copy_review` finding added with PR #46 (`packages/backend/src/harness/skills/deck-skill.ts`, `packages/shared/src/design-audit.ts`) never blocks a turn or an export and has no per-slide review surface in the UI.
- **Import infers only two project types.** `importProject` sets `slide_deck` when the entrypoint contains `[data-slide]` and `prototype` otherwise (`packages/backend/src/services/project-import.ts`, `importProject`), so an exported graphic project re-imports as a prototype and loses its `graphic_set`.

From `doc/14-deliverables-and-platform-publishing-plan-2026-09-09.md` section 12, the questions ADR-015 and doc/15 T07 answered: Q2 (classic Smart Design only), Q3 (root-relative Cafe24 default), Q4 (warning-only Cafe24 lint, blocking Imweb character error), Q6 (additive fields, no V2), Q8 (system-font default), Q9 (seven fields at creation time). Still open: Q1 (test accounts, the cause of T33/T61 above), Q5 (the Codex-only gate on graphic projects is unchanged at `01c42be`; see the generation table), Q7 (which secondary kind ships a full flow first — presets for banner, thumbnail, and print exist but no dedicated flow beyond them), Q10 (WOFF conversion for Cafe24, deferred under T66).
