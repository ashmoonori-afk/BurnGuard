# BurnGuard v0.5.33

BurnGuard v0.5.33 updates built-in theme folders in existing local profiles
when those folders have not been edited since an earlier release, fills in
missing design-system preview cards across the library and new-project format
pickers, and replaces the misleading offline prompt with a clear expired-launch
message when an app launch's access key expires.

## Built-in theme updates and design-system previews

- On every start, BurnGuard now replaces a built-in theme folder in your local
  profile with the version bundled in the app when every file in that folder is
  byte-for-byte identical to a version shipped in an earlier release (ignoring
  line endings). Users who updated from v0.5.31 or earlier without editing the
  classic themes now receive the BurnGuard color palettes introduced in
  v0.5.32 (correcting the v0.5.32 note that upgraded installs keep old theme
  files), and the retired liquid-glass effect copy inside a theme is removed
  only when all of its files match a shipped release. Any built-in theme folder
  you edited stays untouched, font files you added to a theme's `fonts/` folder
  are carried over, and files already generated inside existing projects are
  not modified (new generations with an updated theme use its current files).
  If updating one theme fails, that theme keeps its previous copy, a warning is
  logged, and BurnGuard still starts; an update interrupted part-way is
  restored on the next start before seeding.
- Two built-in sample systems (**Northvale** and **Splash**) no longer store a
  placeholder preview path in the profile that never loaded, and existing
  profiles are cleaned up on the next start.
- A design system without its own preview image now uses the latest website
  project (or, if none exists, the latest project of another format) rendered
  with that system as its card preview, and new-project format pickers (such as
  **Graphic** and **Logo design**) fall back to a system's general preview instead of
  showing a blank "No preview" card when no format-specific preview exists.

## Expired app launch handling

- BurnGuard secures each app launch with a per-launch access key. When that
  launch's access expires (for example, after the app restarts in the
  background with a new key), the workspace no longer appears offline or offers
  a page reload that cannot restore access. Instead, the open workspace and any
  unsent draft stay on screen while BurnGuard shows **This app launch has
  expired** with guidance to reopen BurnGuard from its app shortcut or a fresh
  launch link, and requests that require access are stopped locally with **This
  app launch has expired. Reopen BurnGuard to send a request.**
- Real network outages continue to show the **Reconnect** option, and reloading
  the page while the current launch is still valid keeps working. Startup
  errors now distinguish between denied access, a network failure, and other
  startup failures (**Could not prepare this workspace. Try again or reopen
  BurnGuard.**) in Korean, English, and Simplified Chinese. Backend security
  rules are unchanged.

## Installation

Use the Windows x64 installer or portable ZIP, or the macOS arm64 installer
or portable ZIP. Extract portable packages completely before opening them.
Packages remain unsigned: Windows may require **More info → Run anyway**;
macOS may require **System Settings → Privacy & Security → Open Anyway**.
Verify downloads against the platform-specific SHA-256 files.
