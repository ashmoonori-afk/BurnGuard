# BurnGuard

**이미 쓰고 있는 Claude Code나 Codex에 연결해 작동하는 오픈소스 로컬 디자인 작업 공간이에요.**

![한 줄 프롬프트가 BurnGuard 랜딩페이지가 되고, 캔버스에서 제목을 고치는 장면](doc/images/burnguard-demo.gif)

*v0.5.31에서 Claude Code(Sonnet, 추론 강도 Low)로 디자인 시스템 없이 녹화했어요. 약 71초 동안 진행된 생성과 자동 점검은 빨리 감고 준비와 대기 구간은 잘라냈으며, 프롬프트 입력과 제목 수정은 실제 속도로 재생되고, 제목 수정 장면을 녹화하기 전에 생성된 본문 문안 중 부정확한 문장 하나를 캔버스에서 먼저 고쳤어요.*

⭐ BurnGuard가 시간을 아껴 드렸다면, GitHub 스타 하나가 다른 분들이 BurnGuard를 찾는 데 도움이 돼요.

AI로 웹사이트, 슬라이드 덱, 그래픽, 로고를 만들고 실시간 캔버스에서 바로 고친 뒤 모든 파일을 내 컴퓨터에 보관하세요. BurnGuard는 Windows와 macOS용 로컬 데스크톱 작업 공간이에요. 사용 중인 Claude Code 또는 Codex CLI를 연결하고 디자인 시스템을 골라 실시간 미리보기 옆에서 다듬어요. 프로젝트와 디자인 시스템은 내 컴퓨터에 남고, AI 요청만 선택한 제공업체로 전달돼요.

[사용자 안내서(영문)](doc/user-guide.md): 첫 웹사이트 만들기, 이미지 한 장만 고치기, 다른 컴퓨터로 프로젝트 옮기기, 로컬 파일 위치 찾기를 안내해요.

*번들 SONNEL 웹사이트를 열어 둔 실제 편집기예요. 왼쪽에서 모델을 고르고 오른쪽에서 렌더링된 화면을 보며 미리보기, 편집, 코멘트를 오갈 수 있어요.*

## 디자인 방향으로 시작하기

프로젝트 형식을 고르고 아이디어를 적은 뒤, 필요하면 등록된 디자인 시스템을 선택해요. 프로젝트 이름은 아이디어에서 자동으로 제안되고, 대상 독자 입력란은 선택 사항이며, 디자인 시스템 추천은 최대 4개까지 바로 보여요. 세부 브리프 옵션은 **고급 설정** 안에 들어 있어요. **만들고 생성하기**를 선택하면 프로젝트가 만들어지고 입력한 아이디어가 첫 번째 요청으로 즉시 전송돼요. 처음 설치해 실행하면 홈 화면에 닫을 수 있는 첫 실행 안내 카드가 나타나 Claude Code와 Codex 연결 상태를 확인하고, 같은 카드에서 첫 웹사이트 프로젝트를 바로 만들고 생성할 수 있어요. 디자인 시스템 없이 시작해도 돼요.

기본 카탈로그에는 **테마 43개**가 들어 있고, 그중 **오리지널 테마가 33개**예요. 각 테마는 타이포그래피와 색상 토큰에 더해 내비게이션, 히어로, 푸터 레이아웃 규칙을 갖추고 있어요. 오리지널 샘플 디자인 시스템과 프롬프트 프리셋도 각각 레이아웃 규칙을 갖추고 있어요. 지원하는 문서 파일, 웹사이트, Git 저장소, Figma 파일 또는 단일 `DESIGN.md` 마크다운 파일에서 내 디자인 시스템을 가져와 검토하고 게시한 뒤 프로젝트에 쓸 수 있어요. 등록된 모든 시스템과 기본 제공 테마는 `DESIGN.md` 파일 하나로 내려받을 수도 있고, 시스템마다 최대 60개의 **지킬 것(Do)** 및 **하지 말 것(Don't)** 규칙을 저장해 해당 시스템을 쓰는 모든 생성에 포함해요. [기본 레이아웃 43개 보기](<design system themes/>)

![형식 칩, 디자인 시스템 검색, 새로 고침 버튼과 시스템 선택이 있는 새 프로젝트 만들기 대화상자](doc/images/readme-design-system-picker.png)

*형식 칩, 디자인 시스템 검색, 새로 고침이 있는 새 프로젝트 만들기 대화상자예요. 등록된 시스템이나 기본 제공 테마를 고르거나 디자인 시스템 없이 시작할 수 있어요.*

시스템 개요를 열면 내비게이션, 히어로, 푸터 규칙을 읽을 수 있어요. **방향 시안과 본 생성은 간결 모드를 포함해 같은 레이아웃 규칙을 써요.** 방향 미리보기 3개는 선택한 시스템의 구조 안에서 메시지, 근거, 주요 행동 유도의 비중만 다르게 구성해요. 방향 미리보기는 구조 요약이며, 실제 렌더링된 페이지에는 더 자세한 내용이 들어갈 수 있어요. 시스템을 고르기 전이나 규칙을 바꾼 뒤에 이전에 저장한 방향이 있다면 현재 시스템 기준으로 다시 만들 수 있어요.

![간결한 내비게이션·히어로·푸터 규칙, 그리드 다이어그램, 레이아웃 치수가 보이는 디자인 시스템 개요](doc/images/readme-layout-overview.png)

*Cobalt Atelier 개요 화면이에요. 내비게이션, 히어로, 푸터 요약이 항상 보이고 영역을 펼치면 전체 규칙을 확인할 수 있어요. 빠진 기본 규칙은 자동으로 채워지고 직접 수정한 규칙은 그대로 유지돼요.*

![모델을 Sonnet, 추론 강도를 Low로 둔 상태에서 Cobalt Atelier 레이아웃 규칙을 보여 주는 프로젝트의 방향 정하기 탭](doc/images/readme-layout-direction.png)

*모델을 Sonnet, 추론 강도를 Low로 둔 상태에서 같은 Cobalt Atelier 레이아웃 규칙을 보여 주는 프로젝트의 방향 정하기 탭이에요. 이 화면은 설정된 가이드를 보여 주며 모델 품질 측정 결과가 아니에요.*

데스크톱 패키지에는 **웹사이트 예제 43개**, **생성한 WebP 일러스트 43개**, **헤드리스 브라우저에서 캡처한 웹사이트 썸네일 43개**가 포함돼요. 디자인 시스템 라이브러리와 새 프로젝트의 시스템 선택 창에 이 썸네일이 표시되고, 각 테마 개요에는 스크롤할 수 있는 웹사이트 미리보기가 있어요. [웹사이트 미리보기 갤러리](design%20system%20themes/previews/index.html)와 [테마 토큰 카탈로그](design%20system%20themes/catalogue.html)에서 살펴보세요.

![BurnGuard에서 실제 웹사이트 썸네일을 보여 주는 디자인 시스템 라이브러리](doc/images/readme-design-system-library.png)

*번들 웹사이트 썸네일을 보여 주는 디자인 시스템 라이브러리예요.*

이 예제들은 각 기본 제공 테마의 기본 구성을 보여 줘요. 시스템에 자체 미리보기 파일이 있으면 그것을 먼저 보여 주고, 없을 때는 수정한 시스템 파일이나 게시 상태를 덮어쓰지 않고 번들 레퍼런스를 표시해요. 앱 안에서 모든 예제는 공유 로컬 글꼴 저장소에서 글꼴을 불러와요.

**글꼴 패밀리 72종**이 라이선스 안내와 함께 들어 있어요. 기본 글꼴은 하나의 공유 로컬 저장소에 보관되며, 캔버스에서 불러온 글꼴은 앱 창 안에서 프로젝트끼리 재사용돼요. 새 프로젝트는 이 저장소를 참조하고, 독립 실행형 내보내기에는 문서가 실제로 쓰는 글꼴 파일만 담겨요. [글꼴 목록](assets/fonts/README.md) · [디자인 시스템 형식](<design system sample/README.md>)

## 하나의 작업 공간, 다양한 결과물

| 만들기 | 다루는 내용 | 내보내기 |
|---|---|---|
| 웹사이트 | 연결된 여러 페이지, 공유 스타일시트, 이미지, 재사용 섹션 | HTML, CSS, JS, 에셋 ZIP 또는 내 Vercel 계정에 게시 |
| 슬라이드 덱 | 슬라이드 미리보기, 타이포그래피, 프레젠테이션 모드, 코멘트 | HTML, PDF, PPTX |
| 그래픽 | 사용자 지정 아트보드 크기, 포스터, 여러 프레임 세트 | PNG, PNG 묶음, PDF |
| 로고 | 여러 라운드의 시안 탐색과 마스터 선택 | 마스터 SVG¹, 브랜드 가이드라인 PDF 또는 HTML 아카이브 |
| 상세페이지 | 섹션 이미지가 들어간 긴 세로 페이지 | 섹션 경계에 맞춘 PNG 또는 JPEG 조각 |
| 플랫폼 페이지 | 카페24 스마트디자인 또는 아임웹 코드위젯 패키지 | 단계별 수동 설치 가이드가 포함된 패키지 |

¹ 마스터 SVG 내보내기는 로고 프로젝트에서만 지원해요.

![발표·내보내기 컨트롤이 있는 SONNEL 덱을 보여 주는 BurnGuard 슬라이드 편집기](doc/images/readme-slide-workspace.png)

*같은 작업 공간에서 상단 바의 발표 및 내보내기 컨트롤로 슬라이드 덱을 편집하는 모습이에요.*

PPTX 내보내기는 각 슬라이드에 고해상도 이미지를 배치하고 슬라이드 문안을 발표자 노트에 넣어요. 개별 요소는 BurnGuard의 HTML 작업 공간에서 계속 고칠 수 있으며, 편집 가능한 슬라이드 도형으로는 변환되지 않아요.

## 보이는 곳에서 바로 다듬기

- **캔버스에서 직접 편집해요.** 요소를 눌러 글자, 링크, 이미지 경로, 크기, 회전, 타이포그래피, 간격, 색상을 고칠 수 있어요. 웹사이트 프로젝트는 캔버스 상단 바에 **맞춤**, **데스크톱 1440**, **태블릿 768**, **휴대폰 390** 화면 너비 버튼이 있어 내보내기 전에 반응형 레이아웃을 확인할 수 있어요. 저장 이력, 변경 전후 진입점 썸네일, 실행 취소로 이전 버전으로 돌아갈 수 있어요.
- **코멘트를 고정하거나 상시 규칙으로 저장해요.** 캔버스를 눌러 요소에 피드백 핀을 꽂고 AI 수정 요청을 보내세요. 핀은 스크롤해도 요소를 따라가고, 저장된 핀을 누르면 코멘트가 다시 열려요. 캔버스 위에서 Windows와 Linux는 **Alt+C**, macOS는 **Option+C**를 누르면 빠른 코멘트 창이 열려요. 대화창에서는 첫 브리프 이후의 요청마다 **규칙으로 남기기**를 눌러 수정 내용을 디자인 시스템의 지킬 것 또는 하지 말 것 규칙으로 저장하거나 프로젝트 지침에 추가할 수 있어요. 상단 바의 **프로젝트 지침**에서는 매 요청마다 함께 보낼 기준(최대 4,000자)을 편집할 수 있어요.
- **참고 자료를 첨부해요.** 지원하는 PDF, PPTX, DOCX, 이미지, 텍스트 파일을 첨부하거나 내보낸 HTML 프로젝트 ZIP 또는 `.burnguard-project` 백업 파일을 가져올 수 있어요. 업로드한 원본 파일은 게시용 웹사이트 에셋과 분리해 보관해요.
- **내보내기 전에 품질을 점검해요.** 품질 점검과 UX 진단 패널이 레이아웃, 대비, 링크, 문안을 확인하고 AI에 수정을 요청해요. 점검 결과는 참고용이므로 내보내거나 게시하기 전에 렌더링된 화면을 직접 확인하세요.

내보내기 메뉴의 **인쇄 점검** 대화상자는 인쇄 크기 기준 이미지 해상도를 계산해 300ppi 미만은 경고, 150ppi 미만은 강한 경고로 표시해요. `<img>` 요소는 자른 뒤 남는 원본 픽셀을 재고, 인라인 스타일과 스타일시트의 CSS `background-image` 주소(여러 겹 배경과 인쇄 전용 배경 포함)는 실제로 그려지는 `background-size` 타일 크기를 기준으로 측정해요. 프로젝트에 넣기 전에 이미 확대된 원본 이미지 파일인지는 감지하지 못해요.

### 이미지, 차트, 3D

제품 히어로, 캠페인 장면, 설명 일러스트, 배경처럼 이미지마다 분명한 역할을 지정할 수 있어요. BurnGuard는 13개 분야에 걸쳐 **이미지 표현 방식 21가지**와 **용도별 레시피 38가지**를 제공해요. 생성 이미지는 **실사 사진이 기본값**이에요. 따로 요청하지 않으면 추상 이미지를 만들지 않으며, 프롬프트는 촬영 브리프 형식으로 작성되고, 플라스틱 같은 피부나 번지는 배경, 깨진 글자 같은 생성 결함은 검수에서 걸러내요. 비사진 표현 방식은 직접 선택하거나 요청했을 때만 써요. 새 이미지를 만드는 작업은 연결한 제공업체가 이미지 생성을 지원해야 하며, 그래픽과 로고 생성에는 로그인된 Codex 연결이 필요해요. **차트** 패널에서 영역, 선, 막대, 혼합, 방사형, 원형, 원형 진행률, 생키(Sankey) 차트를 추가할 수 있어요. 스프레드시트에서 탭으로 구분된 행을 붙여넣고 색상을 바꾼 뒤 원본 데이터를 품은 SVG 차트를 HTML 안에 저장해요. **3D** 패널에서는 기본 3D 오브젝트를 다루고 AI에 장면 수정을 요청할 수 있어요. [차트 가이드](doc/charts.md)

4가지 오리지널 샘플 컬렉션인 **SONNEL**, **FOLIOVER**, **ODDWARD**, **VELUNE**를 살펴보세요. 각 컬렉션에는 웹사이트, 6장 구성 슬라이드 덱, 그래픽, 디자인 시스템이 들어 있어요. 홈의 예제 화면에서는 12개 샘플 카드마다 **이 예제를 만든 브리프 보기**로 한국어, 영어, 중국어 간체 대상과 목표를 읽고, **이 예제로 시작하기**를 눌러 현재 인터페이스 언어로 미리 채워진 새 프로젝트 창을 열 수 있어요. ## 시작하기

1. **설치해요.** [GitHub Releases](https://github.com/ashmoonori-afk/BurnGuard/releases/latest)에서 Windows 또는 macOS 설치 프로그램이나 포터블 ZIP을 내려받으세요. Windows에서는 설치 프로그램을 실행하거나 포터블 ZIP 전체를 압축 해제한 뒤 `BurnGuard.exe`를 열어요. macOS에서는 설치 프로그램을 실행하거나 포터블 앱을 응용 프로그램 폴더로 옮겨요. 배포 패키지는 현재 서명되어 있지 않아요.
   - **macOS:** 첫 실행 시 Gatekeeper가 실행을 막아요. 앱을 한 번 열어 본 뒤 **시스템 설정 > 개인정보 보호 및 보안 > 그래도 열기**를 선택하세요. 터미널에서 `xattr -dr com.apple.quarantine "/Applications/BurnGuard.app"` 명령을 실행해도 돼요. macOS 15 이상에서는 아이콘을 Control-클릭해 여는 방식이 동작하지 않으므로 시스템 설정을 이용하세요.
   - **Windows:** 서명되지 않은 설치 프로그램이나 실행 파일을 열 때 SmartScreen이 "Windows의 PC 보호" 안내를 띄울 수 있어요. **추가 정보**를 누른 다음 **실행**을 누르세요.
2. **예제를 열어 봐요.** AI 도구를 연결하기 전에 번들 샘플 프로젝트를 열어 캔버스를 먼저 써 보거나, 예제 카드에서 **이 예제를 만든 브리프 보기**와 **이 예제로 시작하기**를 눌러 보세요.
3. **CLI를 연결해요.** Claude Code 또는 Codex CLI를 설치하고 로그인한 뒤 설정에서 사용할 도구와 모델을 선택하세요. **바닐라 모드가 기본으로 켜져 있고, 추론 강도는 모델이 지원하면 보통(medium)이 기본값이에요.** 보통 강도를 지원하지 않으면 첫 번째 지원 강도를 고르고, 지원 강도 정보가 없으면 낮음(low)을 써요. 바닐라 모드는 개인 CLI 플러그인과 전역 지침을 제외하고 BurnGuard의 프로젝트 맥락만 전달해요.
   - **Codex 작업 진행 감지(기본 켜짐):** 긴 HTML 페이지를 작성하는 것처럼 출력 없이 오래 걸리는 Codex 단계가 멈춘 작업으로 오인되지 않도록 이 컴퓨터의 BurnGuard가 로컬 Codex 사용량 지표를 받아요. 설정에서 **Codex 작업 진행 감지**를 끌 수 있어요. 이미 Codex에 별도의 OpenTelemetry 수집기를 설정해 두었다면, 로컬 감지가 켜져 있는 동안 외부 수집기로 지표가 가지 않으므로 직접 켜기 전까지는 자동으로 꺼져 있어요.
4. **프로젝트를 만들어요.** 아이디어를 적고 필요하면 디자인 시스템을 고른 뒤 **만들고 생성하기**를 눌러 프로젝트 생성과 첫 생성을 한 단계로 시작해요.
5. **내보내거나 게시해요.** **내보내기**에서 독립 파일을 내려받거나, 프로젝트 상단 바의 **프로젝트 폴더 열기**로 파일 관리자에서 로컬 파일을 확인하거나, 웹사이트는 **공유 → 현재 결과물 준비 → 공개 게시**를 눌러 저장해 둔 Vercel 토큰으로 배포하세요.

| 요구 사항 | 세부 내용 |
|---|---|
| Windows 데스크톱 | Windows 10/11 x64, .NET Framework 4.8, WebView2 Runtime |
| macOS 데스크톱 | Apple silicon 기반 macOS 14 이상 |
| AI 생성 | 설치 및 로그인이 완료된 `claude` 또는 `codex` CLI와 해당 제공업체 계정 |
| 렌더링과 내보내기 | 지원되는 로컬 Chromium 계열 브라우저(상태는 설정에서 확인) |
| 업데이트 | Windows 및 macOS 릴리즈 피드(패키지를 교체할 때 로컬 프로필 폴더 유지) |

웹사이트 공개 게시에는 개인 Vercel 토큰과 선택 사항인 팀 ID가 필요해요. 공유 창에 바로 붙여넣은 토큰은 해당 게시 작업 동안만 메모리에 머물고, 설정에 저장한 토큰은 이 컴퓨터의 로컬 설정 파일에만 저장돼요. 호스팅 한도와 방문자 접근 권한은 Vercel 계정 설정을 따라요. 카페24와 아임웹 내보내기 패키지는 수동으로 업로드해야 하며, 실제 운영 중인 고객 쇼핑몰에서는 검증하지 않았어요.

## 내 프로젝트는 내 컴퓨터에 남아요

BurnGuard는 SQLite 데이터베이스, 프로젝트, 설정, 디자인 시스템, 내보내기 캐시를 `~/.burnguard`(Windows에서는 `%USERPROFILE%\.burnguard`)에 저장해요. 앱을 업그레이드할 때 이 폴더를 유지하세요. 열린 프로젝트에서 **프로젝트 폴더 열기**를 누르면 Finder, 파일 탐색기 또는 시스템 파일 관리자에서 해당 폴더를 바로 열 수 있어요.

생성을 실행하면 선택한 프로젝트 맥락이 설정한 AI 제공업체로 전송돼요. 주소(URL)로 가져오기나 웹사이트 게시도 네트워크를 사용해요. 로컬 백엔드는 `127.0.0.1`에서만 요청을 받고, 매 요청마다 실행 권한을 확인하며, 프로젝트 페이지를 샌드박스 iframe 안에서 렌더링해요. [보안 모델](doc/01-architecture.md#7-security-and-safety-model)

## 소스에서 실행하기

CI에 고정된 버전과 같은 **Bun 1.3.14**를 사용하세요.

```sh
git clone https://github.com/ashmoonori-afk/BurnGuard.git
cd BurnGuard
bun install --frozen-lockfile
bun run scripts/dev-launcher.ts
```

런처는 프런트엔드를 `http://127.0.0.1:5173`에서, 백엔드를 `http://127.0.0.1:14070`에서 실행해요. 종료하려면 Ctrl+C를 누르세요. macOS에서는 Finder에서 `Start-BurnGuard.command`를 두 번 클릭해 같은 개발 스택을 켤 수 있고(Bun 필요), 터미널 창을 닫으면 서버가 멈춰요. Windows에서는 `Start-BurnGuard.bat`이 개발용으로 소스에서 데스크톱 래퍼를 빌드하고 실행해요(Bun과 .NET 8 SDK 필요). 소스 파일을 수정한 뒤에는 `--rebuild` 옵션을 붙이세요. 일반 사용자는 소스 런처 대신 GitHub Releases에서 배포 패키지를 받아 설치하세요.

저장소에 들어 있는 기본 테마 페이지를 바로 보려면 브라우저에서 `design system themes/previews/index.html`을 여세요. 이 페이지들은 저장소의 로컬 글꼴과 일러스트를 사용해요. 테마 토큰을 수정한 뒤에는 토큰 카탈로그와 웹사이트 미리보기를 다시 빌드하세요.

```sh
bun run catalogue
bun run previews
```

`previews`는 이미지 생성기를 호출하지 않고 기존 일러스트를 재사용해 HTML 파일을 다시 만들어요. 이후 커밋된 웹사이트 썸네일 이미지를 다시 캡처하려면 Node.js와 로컬 Chromium 계열 브라우저가 설치된 환경에서 `bun run previews:thumbnails`를 실행하세요.

```sh
bun run typecheck
bun run check:whitespace
bun run build:frontend
node packages/backend/node_modules/playwright-core/cli.js install chromium
bun test
```

테스트 preload가 격리된 임시 프로필 폴더를 만들 수 있도록 반드시 저장소 루트에서 테스트를 실행하세요. 브라우저 테스트에는 Node.js가 필요하며, `bun install` 뒤에 위 명령으로 Playwright 브라우저 빌드를 설치하세요. 해당 빌드가 없으면 브라우저 브리지는 준비 상태 점검과 같은 순서로 시스템에 설치된 브라우저 채널을 대신 사용해요. 브라우저 QA에는 Node.js와 로컬 Chromium 계열 브라우저가 필요하며, Windows 러너에서는 `bun.exe`의 전체 경로를 지정해야 할 수 있어요. ### 코딩 에이전트에서 프로젝트 읽기

파일을 내보내고 다시 가져오지 않아도 사용 중인 코딩 에이전트가 실행 중인 BurnGuard 프로젝트를 직접 읽을 수 있어요. 소스 체크아웃에서 다음 명령을 실행하세요.

```bash
bun scripts/burnguard-read.ts projects                 # 활성 프로젝트 목록: id, 종류, 이름, 디자인 시스템
bun scripts/burnguard-read.ts project <id>             # 마크다운 브리프 출력: 디렉터리, 프로젝트 지침, 디자인 시스템 규칙, 파일 목록
bun scripts/burnguard-read.ts project <id> --json
```

이 명령은 `BG_APP_ROOT`(기본값 `~/.burnguard`)의 프로필 데이터베이스를 읽기 전용으로 열며, 디스크에 아무것도 쓰지 않고 네트워크 포트도 열지 않으므로 BurnGuard가 켜져 있는 동안에도 안전하게 실행할 수 있어요.

## 변경 내역

### 0.5.34

- 디자인 시스템에서 색상 토큰을 저장하거나 토큰 스타일시트가 있는 시스템에 글꼴 역할이 지정된 글꼴을 올리면 열려 있는 프로젝트의 디자인 기준 후보를 바로 다시 확인하며, 직접 새 기준을 적용하기 전까지 프로젝트의 기존 기준은 그대로 유지해요.
- **실험적 결정론적 PNG 로고 트레이싱**은 선택한 로고 후보를 최종 확정할 때 AI 턴보다 먼저 최대 8색의 간결한 `logo.svg`를 만들고, 크기나 복잡도 한도를 넘으면 기존 AI 벡터화 경로로 자동 전환해요.
- 백엔드 `hono`를 `4.13.13`으로, 프런트엔드 `vite`를 `6.4.5`로 업데이트하여 `hono`, `vite`, `launch-editor`의 보안 권고 6건을 해결했어요.

### 0.5.33

- 앱을 시작할 때마다 로컬 프로필의 기본 제공 테마 폴더가 이전 정식 릴리즈에서 배포된 파일과 바이트 단위로 똑같으면(줄바꿈 차이 제외) 현재 번들 버전으로 교체하여, v0.5.31 이전에서 업데이트한 환경에서도 직접 수정하지 않은 클래식 테마가 v0.5.32의 새 BurnGuard 팔레트로 업데이트돼요. 사용자가 수정한 테마 폴더와 테마의 `fonts/` 폴더에 추가한 글꼴 파일, 기존 프로젝트 안에 이미 생성된 파일은 건드리지 않으며, 교체 도중 중단된 테마는 다음 시작 때 복원하고 개별 테마 업데이트에 실패하면 이전 복사본을 유지한 채 경고를 남기고 정상 시작해요.
- 기본 제공 샘플 시스템인 **Northvale**과 **Splash**에서 불러오지 못하던 임시 미리보기 경로를 제거하고 다음 시작 시 기존 프로필도 함께 정리하며, 자체 미리보기 이미지가 없는 디자인 시스템은 해당 시스템으로 렌더링한 프로젝트 하나를 카드 미리보기로 보여 주고(웹사이트부터 정해진 형식 순서로 고르며, 같은 형식 안에서는 가장 최근에 수정한 프로젝트) 새 프로젝트 형식 선택기(**그래픽**, **로고 디자인** 등)에서도 형식별 미리보기가 없을 때 빈 "미리보기 없음" 카드 대신 일반 미리보기를 표시해요.
- 백그라운드 재시작 등으로 실행별 접근 키가 만료되었을 때 오프라인 상태로 표시하거나 권한을 갱신할 수 없는 새로 고침을 권하는 대신, 열려 있는 작업 공간과 전송 전 초안을 화면에 그대로 두고 **이 실행의 접근 권한이 만료됐어요** 안내와 함께 앱 바로가기나 새 실행 링크로 다시 열도록 안내해요. 실제 네트워크 끊김은 기존처럼 **다시 연결**을 표시하고, 시작 오류도 접근 거부·네트워크 실패·기타 준비 오류를 한국어, 영어, 중국어 간체로 구분해 알려 줘요.

### 0.5.32

### 0.5.31

- 프로젝트를 만들 때 아이디어를 먼저 적으면 편집 가능한 프로젝트 이름이 제안되고 대상 독자 입력란은 선택 사항이 되었으며, **만들고 생성하기**를 누르면 첫 요청을 바로 보내요(전송에 실패하면 입력창에 초안을 남겨요). 처음 설치한 환경에서는 홈에 닫을 수 있는 첫 실행 안내 카드가 나타나 Claude Code와 Codex 연결을 확인하고, 번들 예제 카드 15개마다 한국어, 영어, 중국어 간체 브리프를 읽고 새 프로젝트를 바로 시작할 수 있어요.
- 디자인 시스템마다 최대 60개의 **지킬 것(Do)** 및 **하지 말 것(Don't)** 규칙(각 280자 이내)을 저장해 모든 생성에 포함하며, 기본 제공 테마를 포함한 모든 등록 디자인 시스템을 단일 `DESIGN.md` 파일로 내려받거나 `.md` 파일에서 가져올 수 있어요. 저장된 규칙 목록이 손상되었을 때 생성과 시스템 화면은 유효한 규칙만 읽고 손상된 항목은 건너뛰며, 규칙 편집 시에는 손상된 목록 덮어쓰기를 막아요.
- 프로젝트마다 매 요청에 함께 전달되는 **프로젝트 지침** 대화상자(최대 4,000자, `.burnguard-project` 백업에 포함)가 생겼어요. 대화창의 후속 메시지에서는 **규칙으로 남기기**로 수정 내용을 디자인 시스템의 지킬 것 또는 하지 말 것 규칙으로 저장하거나 프로젝트 지침에 추가할 수 있어요.
- 웹사이트 프로젝트의 캔버스 상단 바에 **맞춤**, **데스크톱 1440**, **태블릿 768**, **휴대폰 390** 미리보기 너비 버튼을 추가했어요. 저장 이력과 현재 원본 비교 화면에서 변경 파일 목록 옆에 보관된 변경 전후 썸네일을 보여 주고, 스냅샷을 쓸 수 없을 때는 안내 문구를 표시해요.
- 프로젝트 상단 바의 **프로젝트 폴더 열기**로 Finder, 파일 탐색기 또는 시스템 파일 관리자에서 프로젝트의 로컬 폴더를 열 수 있어요. 소스 체크아웃에서 `bun scripts/burnguard-read.ts`를 실행하면 로컬 프로필 데이터베이스를 읽기 전용으로 열어 BurnGuard가 켜져 있는 동안 코딩 에이전트가 활성 프로젝트 목록이나 브리프, 지침, 디자인 시스템 규칙, 파일 목록을 확인할 수 있어요.
- **인쇄 점검**이 인라인 스타일과 스타일시트의 CSS `background-image` 주소를 실제 그려지는 타일 크기로 측정하고 원본 파일의 사전 확대 여부는 감지하지 못한다고 안내하며, 번들 브라우저가 없을 때는 시스템에 설치된 브라우저를 대신 사용해요. 생성 도중 BurnGuard가 예기치 않게 종료되면 다음 실행 때 프로젝트 파일을 복원하기 전에 아직 실행 중이던 AI 도구 프로세스를 먼저 멈추고, 멈춘 것을 확인하지 못하면 오류를 표시하며 시작을 중단해요.
- 라이트 모드와 다크 모드 전반에서 포커스 윤곽선, 로딩 및 빈 상태 화면, 툴팁, 글자와 컨트롤의 대비를 개선했고, 프로젝트 상단 바와 캔버스 툴바는 한 줄을 유지하며 좁은 화면에서는 **더보기** 메뉴와 하단 시트 모드 패널을 사용해요. 내보내기 메뉴는 **내보내기 설정**, **인쇄 점검**, **최근 내보내기**를 별도 대화상자로 열고 플랫폼 가이드를 대화상자 안 단계 화면으로 보여 주며, 문서에 `doc/user-guide.md`와 `Start-BurnGuard.command` 안내를 추가했어요.

### 0.5.30

- 디자인 검토에서 거부된 생성 결과를 별도의 미검증 초안으로 열 수 있어요. 원래 프로젝트, 리비전, 검토 결과는 그대로 남고, 초안은 실패한 검토에서 확인하지 못한 항목이 현재 내용의 검토에서 모두 통과할 때까지 미검증으로 표시돼요. 보관 기간이 지났거나 손상됐거나 게시할 수 없는 결과는 이유와 함께 거부돼요.
- 수정 요청을 글자만 또는 이미지만으로 제한할 수 있고, 페이지, 아트보드, 요소를 골라 범위를 좁힐 수도 있어요. 게시 전에 이전 리비전과 비교해(글자, 이미지 참조, CSS 배경과 함께 쓰는 이미지를 포함한 파일 내용, 스타일, 스크립트, 구조, 화면에 보이는 공백) 범위를 벗어난 변경은 게시하지 않아요. 기록에는 바뀐 페이지, 바뀐 종류, 글자 변경 전후가 보여요. 화면 픽셀이 아니라 원본 기준 비교예요.
- 내보내기 메뉴에 인쇄 점검이 생겼어요. 페이지 크기, 없거나 외부에서 불러오는 글꼴, 브라우저 준비 상태, 자른 뒤 이미지의 실제 해상도를 확인해요(300ppi 미만 경고, 150ppi 미만 강한 경고, `<img>` 요소의 원본 픽셀만 측정). 내보내기 단계마다 제한 시간이 있고, 멈추거나 실패한 단계와 해결 방법을 알려 줘요.
- 키보드 초점을 받을 때 나타나는 건너뛰기 링크를 더 이상 글자 넘침으로 보고하지 않고, 요소 ID가 없는 항목도 선택자와 위치로 찾을 수 있어요.
- 실제 사물 사진에 배치 기록(출처가 있는 참조 사진, 크기, 에이전트가 보고한 참조 첨부 여부, 비교한 후보, 자르기 배치)을 남길 수 있고, 기록이 모두 갖춰졌을 때만 참조 확인됨으로 표시돼요. 늘어난 사진과 게시 파일에 들어간 참조 사진은 반드시 고칠 항목이에요.
- Windows에서 브라우저 기반 점검이 느린 첫 실행 때문에 중간에 실패하던 문제를 고쳤어요.

### 0.5.29

- 체크포인트 스냅샷이 무결성 매니페스트와 내구성 있는 쓰기로 게시돼요. 중단된 교체는 이전의 검증된 쌍을 복구하고, 완성되지 않은 새 스냅샷은 레거시 데이터로 취급하지 않고 거부해요.

- 내보내기 게시가 검증된 아카이브 다이제스트와 크기 제한을 다시 확인해요. 손상된 체크포인트 영수증이 프로젝트 번들 내보내기를 막지 않아요.
- 공급자 stdout 파싱에 상한이 생겼고, 취소 테스트가 Windows와 POSIX 모두에서 자식·분리 자손 프로세스를 다뤄요. Codex 이미지 알림이 더는 스레드 ID를 담은 파일 이름 힌트에 의존하지 않고, 스캐너가 현재 스레드의 파일을 계속 검증하고 골라요.
- 프로젝트 와처가 폭주를 합치고 종료 시 깔끔하게 정리하며, 브라우저 실행·정리가 전송 안정화와 리소스 수명을 잘 처리해요.
- macOS가 로그인 셸과 Node 매니저 경로에서 공급자 CLI를 찾고, 업데이트 캐시 정리를 다운로드 승인과 직렬화해요. 네이티브 종료·업데이트 대화상자가 현지화됐고, 생성 중 닫기는 확인을 받으며, 코멘트 초안이 다시 열려도 유지돼요.
- 빠른 코멘트가 Alt/Option+C를 사용하고, Ctrl+Y가 두 기록 처리기에서 동작하며, CLI 프로브 실패는 별도의 설명과 복구 안내를 받아요. 너무 큰 가져오기는 지원 한도가 있으면 표시하고 입력한 값을 유지해요.
- 로컬 부트스트랩은 런처가 가진 권한을 요구해요. Origin 헤더만으로는 능력을 얻지 못해요. 토큰이 있는 Figma 요청은 리다이렉트를 거부하고, SVG 방향 미리보기는 보호용 원시 파일 헤더를 받으며, 아카이브 추출은 포함 범위 확인을 사용해요.
- 공급자 로그와 완료 메시지가 개인 스테이징 경로를 드러내지 않아요. Ubuntu CI가 베이스라인 제외 없이 발견되는 모든 테스트 파일을 실행하고 브라우저 적합성·PDF/PNG/PPTX 스모크 점검을 포함하며, 와처·이미지 회귀 테스트는 macOS와 Windows에서도 돌아요.

- 웹사이트 추출이 더 정확해졌어요. 소제목, 브랜드 이름, 색상 토큰, 히어로 이미지를 더 안정적으로 측정하고, 가져온 SVG 이미지를 정리하고, 스타일시트 리다이렉트는 같은 사이트 안에서만 허용하고, 레이아웃을 측정하지 못했을 때는 그 이유를 기록해요.
- 설치된 AI 도구가 없으면 전송이 비활성화되고 이유와 설정 링크가 표시돼요. 중단되거나 실패한 턴은 항상 중단 또는 실패로 표시되고, 다른 메시지가 실행 중일 때 보낸 메시지는 반쯤 기록된 턴을 남기지 않고 깔끔하게 거절돼요.
- BurnGuard가 백그라운드에서 다시 시작되면 열려 있는 창이 알려 주고 새로 고침을 제안해요. 휴대폰 너비에서도 작업 공간, 캔버스 도구, 내보내기를 쓸 수 있어요.
- 모델이 지원하면 추론 강도 기본값이 medium이 되고, 지원 모델 목록은 현재 공식 모델 ID를 사용해요.
- 캔버스는 페이지가 쓰는 글꼴만 불러오고, 페이지가 그려질 때까지 렌더링 상태를 보여 줘요. 스타일 사이드 에디터는 입력한 값을 유지해요.
- 매우 크거나 특이한 프로젝트 파일도 내보내기가 훨씬 빠르고 안전하게 처리돼요. 악센트가 있는 macOS 파일 이름을 유지하고, 다운로드 파일 이름을 올바르게 인코딩해요.
- 오류 메시지에 더 이상 개인 파일 경로나 원시 시스템 오류 문구가 나오지 않고, 설정 오류는 복구 방법을 설명해요. 한국어와 중국어 문구도 보완했어요.
- macOS 앱이 Windows 앱과 같은 데스크톱 규칙을 따르고, 업데이트 확인이 프리릴리즈 버전을 올바른 순서로 정렬해요.

- 콘텐츠와 이미지가 로드될 때 큰 슬라이드 콘텐츠를 아트보드에 맞춰요.
- 생성을 완료로 표시하기 전에 실제 슬라이드 내용, 슬라이드 수, 런타임, 로컬 이미지를 검증해요. 플레이스홀더를 받아들이지 않고 미완성 결과물은 이어서 생성해요.
- 생성 이미지의 기본값을 실사 피사체로 하고 추상적인 장식 이미지를 피해요.
- 기록용 사양서 04부터 23까지와 참고 노트는 로컬에만 두고, 공개 문서 색인을 단순화했어요.

### 0.5.17

- 선택한 프로젝트 형식에 맞는 슬라이드 또는 웹사이트 썸네일을 보여 줘요.
- 생성을 중단해도 생성된 HTML과 에셋을 보존하고, 쓰는 도중 진입점이 사라졌다면 이전 진입점을 복원해요.
- 프로젝트 디자인 규칙을 고정하고, 렌더링된 결과물을 감사하고, 핸드오프 내보내기에 검토 증거를 포함해요.
